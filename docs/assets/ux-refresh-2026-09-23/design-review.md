# 킨다 관제 UI/UX 전면 검토와 적용 시안

작성일: 2026-09-23 · 상태: **제품 구현 전 디자인 제안** · 대상: 고객용 웹, 모바일 웹, 최초 설치, 인증 및 운영 진입

이 문서는 실제 저장소의 기능 계약과 화면 코드를 읽고 만든 검토안이다. PNG의 현장명, 조명 수, 사용량, 비용, 시각, 오류 사례는 모두 **가상 예시 데이터**다. 이미지의 버튼은 정적 시안이며 실제 제품 기능을 실행하지 않는다. 제품 코드, API, DB, 펌웨어, 메뉴 기능 현황 문서는 변경하지 않았다.

## 제안 요약

추천 방향은 **지도 중심 작업대 + 전역 현장 맥락 + 재진입 가능한 상태 센터**다. 운영자가 묻는 순서를 화면에 반영한다: “어느 현장인가 → 어디에 문제가 있나 → 어떤 조명을 조치하나 → 결과를 확인했나.” 설치 담당자에게는 현장·층 → 게이트웨이 → 조명 등록 → 운영 시작의 실제 계약을 그대로 보여 준다.

| 접근 | 장점 | 한계 | 판단 |
| --- | --- | --- | --- |
| A. 기존 카드 중심 정리 | 변경 범위가 작고 출시가 빠름 | 지도·제어·상태가 분리되어 주행 동선과 모바일 높이 문제가 남음 | 과도기 대안 |
| B. 지도 중심 작업대 | 현장 위치와 상태/조치가 같은 맥락에 놓임. 기존 MapSnapshot, ControlTargetPicker, 메뉴 route를 활용 가능 | 지도 없는 조명과 부분 실패의 독립 접근 경로가 필요 | **추천** |
| C. 알림 중심 관제판 | 장애가 가장 먼저 보임 | 미구현 escalation/notification을 실제 제품 기능처럼 보이게 할 위험 | 현재 범위에 부적합 |

시각 언어는 승인된 킨다 마크와 Navy `#15324A`, Blue `#256FA1`, Coral `#FF7A5C`, Paper `#F4F8FA`를 따른다. Coral은 로고 이외의 오류·경고 의미색이나 주요 버튼에 쓰지 않는다. 상태는 기존 `status-success/warning/danger` 의미 토큰을 쓴다. 기존 Tailwind v4 `@theme`가 유일한 제품 색/간격 출처이고, 실제 구현 시 React Aria 기반 공통 `Button`, `SelectBox`, `SidePanel`, `StatusBadge`, `Tooltip`/overlay 계열을 확장하거나 재사용한다. 시안 CSS는 화면 설명용 독립 아티팩트이며 제품 스타일 소스가 아니다.

## 사용자 여정과 우선순위

**시공·유통 파트너:** 현장 확인 → 주소·단가·시간대 입력 → 층 생성/수정 → 게이트웨이 연결 → 조명 검색·일괄/개별 등록 → 미배치 조명을 도면에 배치 → 설치 인계. P1인 층수/실제 `floors` 배열 불일치를 저장 전에 막고, 설치 완료 직후 게이트웨이 연결/조명 등록으로 이어지는 CTA를 둔다. 게이트웨이·층이 하나라면 안전한 기본 선택을 제공하되 다중 선택·세션 복구를 숨기지 않는다.

**시설 운영자:** 전역 현장 선택 → 층 KPI·지도에서 이상 확인 → 조명 상세와 최근 수신/원인 확인 → 제어 가능한 대상만 실행 → 명령 terminal 결과 확인 → 기간별 추이/보고서 확인. 오프라인 조명의 밝기는 현재값처럼 보이지 않게 `최근 확인 밝기`와 마지막 수신 시각을 함께 표시한다. 모니터링 freshness와 제어 가능 여부는 서버 정책이 다를 수 있으므로 하나의 “정상” 배지로 합치지 않는다.

## 페이지별 정보 위계

- **모니터링:** 전체/정상/점검/오프라인은 층 범위를 고정해 표시한다. 데스크톱 지도와 상세 2열, 모바일은 KPI → 지도 → 우선 확인/검색의 빠른 진입 순서다. 390px 시안은 4개 KPI를 한 줄로 줄였고, 320px 설계는 2×2로 고정해 4행 누적을 피한다. 지도 자체의 최소 높이는 320/390px에서 보이는 영역에 맞춰 줄이고 확대 기능을 보존한다. 지도에 배치되지 않은 조명도 검색/목록으로 접근한다. 모바일 지도 개요는 14개 중 일부 마커만 보여 주고 검색/목록으로 전체에 접근한다. 밀집 마커는 개요에서 모두 44px로 겹쳐 놓지 않고 확대 또는 집계한 뒤 선택한다. 검색은 **새 제안**이다. 장비의 `Health fault` 코드는 고객 화면에서 `조명 자체 점검 신호`와 `조명·배선 상태 확인`으로 풀어 쓰고 기술 코드는 상세 정보에 둔다.
- **제어:** 수동 화면에서 지도/목록/구역은 하나의 대상 선택 방식으로 두고 밝기 실행 패널과 결과를 고정한다. 기술 전송 방식은 고객용 전면 설명에서 제외하고 필요 시 도움말에 둔다. 대상/권한/장비 준비 상태를 확인한 뒤에만 실행을 활성화한다. 기존 command lock, 복구, 동일 요청 확인, 부분 실패를 보존한다. 스케줄 적용 종료일은 매일 반복의 유효 기간으로 반드시 노출한다. 모바일 자동화는 수평 스크롤 표 대신 값이 빠짐없는 행 카드 또는 상세 sheet가 적합하다.
- **통계·보고서:** 각 수치를 `측정`(실계측일 때만), `상태 기반 추정`, `비교 기준`으로 명시한다. 오늘은 마감된 하루가 아닌 `00:00–마지막 집계, 진행 중`이다. 0과 미수집은 다른 표기로 둔다. 04 시안의 `추이 9/1–9/23`은 선 그래프와 분석 기간에만 적용하며 y축은 kWh 단위와 눈금을 가진다. 오늘/이번 달/올해 KPI는 각각 현장 시간대의 고정 기간, 비용 비교는 선택한 자체 비교 기간을 사용한다. 히트맵은 가로/세로 축 이름, 시간대, 단계 범례와 결측 패턴을 붙인다. 보고서에서는 검색·상태·요청 기간만 먼저 보이고 형식/범위는 상세 필터로 접는다. 9/23 현지 시각에 생성하는 보고서 본문 범위는 마지막 완료일인 9/22 이내다. 저장 비용은 당시 적용 단가, 비교 기준 비용으로 환산할 때만 생성 시점 current tariff snapshot을 사용한다. PDF/XLSX는 같은 문서 계약을 유지한다. 완료 파일의 만료 시각은 현행 7일 정책에 따라 행 메타나 상세 popover에서 확인한다.
- **설정·도면:** 전역 현장 전환은 공통 상단에서 한 번에 하고, 설정에서는 조명 등록·도면·운영 기준·사용자·보안으로 이동한다. 맵 편집기는 기본 도구/선택 속성을 우선 보이고 CAD/식별/버전 등은 상황별 패널로 열어 작업면을 지킨다. 모바일 배치는 HTML drag/drop의 대안으로 탭 위치 지정 제안을 제공한다. 저장 전 draft와 실제 저장 결과는 시각적으로 구분한다.
- **인증·운영:** `/auth/me`와 로그인 제출의 응답 대기는 영원히 계속되지 않아야 한다. 타임아웃/서버 오류는 재시도 경로를 보여 주고, 실제 인증 실패만 비밀번호 오류로 안내한다. 운영자 화면은 고객용 4개 메뉴의 영역으로 섞지 않는다.

## 경고·실패 표시 계약

페이지마다 안내/경고 블록을 추가해 콘텐츠를 아래로 밀지 않는다. 상태 배지, 아이콘 tooltip, 토스트와 anchor가 있는 popover/drawer를 조합한다. 아래 기준은 상태의 심각도와 복구 가능성에 따른다.

| 상황 | 즉시 표현 | 사라진 뒤 재진입 | 내용·행동 |
| --- | --- | --- | --- |
| 완료/짧은 확인 | 4–6초 toast | 이력 또는 관련 패널 | 성공 결과·대상 |
| 부분 실패/갱신 지연, 기존 데이터 유지 | 짧은 toast + 상단 상태 아이콘 점 | 상태 센터 popover/drawer에 해결 전까지 유지 | 실패한 데이터 출처, 마지막 성공 시각, 재시도 |
| 조명 점검/오프라인 | KPI/마커/목록의 상태와 상태 센터 | 상세 패널, 상태 센터 | 원인, 마지막 수신, 권장 조치, 제어 가능 여부 |
| 명령 접수 후 불확실/부분 실패 | 제어 패널의 진행/결과 overlay | 명령 이력 및 상태 센터 | 같은 요청 확인, 실제 상태 확인, 안전한 재전송 |
| 인증/권한/최초 데이터 로드 차단 | 본문을 대체하는 복구 화면 또는 modal | 재시도/로그인 진입 자체 | 오류 분류, 다음 행동; 이전 데이터가 없는데 정상값처럼 표시하지 않음 |
| 필드 검증/dirty map/삭제 확인 | 필드의 예약된 도움말 자리 또는 dialog | 해당 필드·편집 상태 | 문제 필드로 focus 이동, 취소/확인 의미 유지 |

토스트는 중요한 상태의 유일한 저장소가 아니다. 상태 아이콘에는 읽지 않은/미해결 건수와 접근 가능한 이름을 제공하고, popover는 키보드·Escape·외부 클릭·focus 복귀를 지원한다. 상태 센터는 내부 알림 발송이나 escalation을 뜻하지 않는다. persistent 오류는 해결 조건을 확인해야 제거한다. 이 정책은 [Carbon 알림 사용 지침](https://carbondesignsystem.com/components/notification/usage/)의 자동 닫힘 toast 이후 대체 접근 경로 원칙을 참고했다. 질문 중심 대시보드 정보 순서는 [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)를, 전역 현장 필터의 일관성은 [Datadog template variables](https://docs.datadoghq.com/dashboards/template_variables/)를 참고했다. 이는 킨다의 기존 기능을 넓혀도 된다는 근거가 아니라 위계 설계 참고다.

09 시안의 상태 센터는 **현재 로그인 세션에서 조회 중인 쿼리와 화면 상태를 다시 여는 UI**다. 갱신 실패는 현재 조회 상태에서 재시도하거나 성공 시 해제한다. 조명 점검 항목은 기존 조명/인시던트 데이터의 현재 상태로부터 표시한다. 새 durable alert 이력, 알림 전달, 장기 보관 DB를 제안하지 않는다. 새로고침·현장 전환·로그아웃 후의 재구성은 기존 API 상태가 제공하는 범위에 한정한다.

시안의 상단 `게이트웨이 1/2대 연결 · 확인 필요` 배지는 **새 셸 UI 제안**이다. 현재 `CustomerShell` 상단에는 게이트웨이 배지가 없다. 이 배지는 상단에서 선택한 현장의 게이트웨이 집계만 나타내며 누르면 상태 센터의 해당 현장 게이트웨이 항목으로 이동한다. 층별 조명 오프라인 수나 제어 가능 여부와 동치로 취급하지 않고 각각의 정책·최근 수신 시각을 유지한다. 데이터가 없는 경우는 정상 녹색을 보이지 않고 `확인 불가`로 표시한다.

모바일 시안의 조작 영역은 새로고침·검색·층 선택·줌·맵 마커·배치 위치 확인까지 최소 44×44 CSS px를 목표로 한다. 14–20px 시각 마커와 별도의 44px hit target을 두며, 44px 상자가 서로 겹칠 정도로 밀집하면 개요에서 일부만 표시하고 확대/목록 선택으로 전환한다. 320px에서는 검색을 지도 앞에 놓고 본문만 스크롤하며 하단 메뉴는 계속 보이게 한다.

## 클릭 수와 검증 기준

아래는 **코드의 현재 화면 단계와 제안된 경로를 바탕으로 한 예상치**이며 사용자 테스트나 제품 계측 결과가 아니다.

| 업무 | 현재 코드에서 예상되는 경로 | 제안 경로/목표 |
| --- | --- | --- |
| 다른 현장 모니터링 | 설정 진입 → 현장 선택 → 모니터링 복귀: 약 3회 | 상단 현장 선택 → 현장: 약 2회 |
| 단일 층/게이트웨이 등록 | 층 선택 → 게이트웨이 선택 → 검색 시작: 약 3회 | 하나씩뿐이면 자동 선택 → 검색 시작: 약 1회 |
| 모바일 미배치 조명 위치 지정 | HTML drag/drop에 의존, 터치 정확도 보장 곤란 | 조명 선택 → 지도 탭 → 위치 확인: 3회 |
| 차량 이벤트 규칙 대상 지정 | 센서와 실행 조명 각각 선택, 현재 관찰에서 8회 이상 탭 가능 | 같은 지도에서 단계별 선택; 실제 탭 절감은 프로토타입 사용성 검증 뒤 산정 |
| 보고서 이력 조건 조정 | 5개 필터 노출 | 기본 3개, 상세 조건 선택 시 2개 추가; 작업에 필요한 클릭 수는 유지 |

검증 시 실제 사용자 5–8명의 설치 담당·운영자에게 첫 설치 완료, 다른 현장으로 전환, 오프라인 조명 찾기, 3개 조명 70% 적용, 매일 스케줄 기간 확인, 보고서 재다운로드를 수행시킨다. 성공률·완료 시간·잘못된 대상 선택률·경고 재발견률·역할별 접근성 문제를 기록한다. 자동화에서는 1440/1024/390/320px overflow, 44×44px 조작 영역, 키보드/스크린리더 이름과 focus, 고대비 상태 구분, 부분 실패에서도 데이터 보존, URL `siteId`/기간/뒤로가기, PDF/XLSX 결과 동일성을 확인한다. 실제 iOS/Android WebView와 물리 게이트웨이·조명 HIL은 별도 현장 검증이다.

## 구현 분장과 승인 경계

1. **공통 UI/셸 담당:** 전역 현장 선택과 역할별 모바일 nav, 상태 아이콘/센터, toast/overlay primitive, 인증 복구 프레임. Tailwind semantic token과 React Aria focus 계약 소유.
2. **설치·설정 담당:** 층수↔층 배열 검증, 설치 후 다음 단계 CTA, 단일 선택 기본값, 모바일 탭 배치, 편집기 상황별 패널. DB 스키마는 변경하지 않는 방향.
3. **모니터링 담당:** KPI/지도/검색 목록 위계, 오프라인 밝기 표기, partial/stale 상태 센터 연결, 미배치 접근.
4. **제어 담당:** 수동 결과 패널, schedule 적용 기간 노출, event 센서→조명 선택 흐름, 모바일 행 카드. BIO production 활성화는 별도 장비 검증 전 범위 밖.
5. **통계·보고서 담당:** 현장/기간/timezone 범위 정의, 추정/기준/결측 표현, 상세 필터, 히트맵 범례와 PDF/XLSX 회귀.
6. **QA·접근성 담당:** 사용자 여정 시간 측정, 상태 재발견, 320px 터치, 키보드·스크린리더, URL/권한/부분 실패 회귀.

이 보고서와 PNG는 검토·승인을 위한 결과물이다. 제품 코드 및 별도 구현 spec/plan 작성은 이후 승인 범위에서 수행한다. 실제 UI가 변경될 때는 해당 `docs/menus/{monitoring,control,statistics,settings}.md`를 같은 작업에서 갱신한다.
