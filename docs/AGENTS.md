# 문서 작업 규칙

## 소유 역할과 범위

- 제품 흐름, 화면 명세와 디자인 기준의 기본 담당은 `designer`다.
- 기본 수정 범위는 `docs`이며, 문서에 기록할 실제 구현 상태는 해당 코드 소유 역할의 검증 결과를 기준으로 한다.
- 구현 상태 문서는 해당 기능의 구현 역할이 코드와 같은 작업에서 갱신하고, `qa_reviewer`가 실제 검증 증거와 일치하는지 확인한다.
- 서술 문서는 한글로 작성한다. 명령, 코드 식별자, 제품명처럼 번역하면 의미가 달라지는 값만 원문을 유지한다.

## 정본과 생성 원칙

- 현재 상태 요약의 정본은 `docs/project-status.md`, 운영 기준의 정본은 `docs/agent-operations.md`다.
- 메뉴별 현황은 `docs/menus/*.md`, DB 구조는 `docs/database-schema.md`, 반복 교훈은 `docs/lesson_leared.md`에 누적한다.
- 기존 정본 갱신을 우선하며 작업마다 새 문서를 만들지 않는다. 별도 설계나 실행 계획이 독립적인 장기 기준으로 필요할 때만 총괄 승인 후 새 문서를 만든다.
- 미구현 계획을 구현 완료로 바꾸지 않고, mock·자동 테스트·실장비 HIL 상태를 구분한다.

## 공유 계약과 검증

- 문서에서 API, DB, MQTT, BLE Mesh, 인증서 또는 OTA 계약을 새로 확정하지 않는다. 총괄과 소유 역할이 승인한 계약만 반영한다.
- 경로, 명령, 패키지 이름과 상태를 실제 저장소와 대조한다.
- 활성 `writing-plans` 체크리스트가 있는 작업은 `docs/project-status.md`와 상태를 동시에 갱신한다.
- 문서 변경 후 `git diff --check`를 실행하고 링크·경로·명령의 존재 여부를 확인한다.
