# 공개 랜딩 파일 정리와 통합 실행 체크리스트

**목표:** 공개 랜딩·주요 기능·요금제 적용 후 실제로 사용되지 않는 파일과 오래된 정책 참조를 정리하고, 관련 작업만 검증 가능한 Git 범위로 유지한다.

**경계:** 다른 작업의 미커밋 맵/Final Atlas 파일과 활성 worktree는 보존한다. 사용자가 요청했던 비교용 정적 시안·검토 스크린샷은 의도적인 결과물과 증거이므로 보존한다. `main` 병합은 대상 브랜치 확인 전 진행하지 않는다.

## 1. 사용 여부 감사

- [x] Web production import, 테스트, 정책, 문서 링크에서 기존 랜딩 파일 참조를 검색한다. 삭제된 `landing.css`를 UI 정책/fixture가 아직 허용하는 상태를 확인했다.
- [x] QA의 읽기 전용 감사로 확실한 사장 파일과 보관 기록을 구분했다. 현재 production 랜딩 컴포넌트는 모두 참조되고, `/concepts/`는 전용 E2E·문서에 연결된 요청 결과물이므로 보존한다.

## 2. 정리 및 문서

- [x] 삭제된 `landing.css`를 가리키는 UI 정책 예외와 테스트를 현재 코드 기준으로 고친다. 퇴역 CSS 재도입은 정책 테스트에서 거부한다.
- [x] 비교 시안·스크린샷은 요청 결과와 검토 증거로 보존하고, 사용 여부를 메뉴 문서에서 구분한다.
- [x] 메뉴별 기능 현황과 `docs/project-status.md`를 실제 최종 상태에 맞춘다. 활성 랜딩 CSS의 별도 정책 부채를 명시한다.

## 3. 검증 및 통합

- [x] Web 정책 집중 테스트·typecheck·단위 테스트·build와 관련 브라우저 회귀를 검증한다. 퇴역 CSS 거부 집중 5/5, Web unit 2,371개(3 제외), 랜딩 Chromium 31/31, typecheck/build 통과. 전체 `ui:check`는 활성 랜딩 CSS 등을 포함한 기존 927건으로 실패하고 `test:ui-policy` 전체 61개 중 생산 UI 무위반 단언 1개가 같은 원인으로 실패한다. 후속 리팩터링 대상이다.
- [ ] `git diff --check`, 삭제 후 참조 검색, `/`·`/features`·`/pricing` 로컬 HTTP 응답을 확인한다.
- [ ] 랜딩 정리만 별도 커밋하고 다른 미커밋 작업을 보존한다. 대상이 확인되면 지정 브랜치에 반영한다.
