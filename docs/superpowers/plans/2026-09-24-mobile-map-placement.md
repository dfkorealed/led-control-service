# 모바일 맵 배치 구현 계획

> 기존 `FloorEditorView`/`FloorEditorCanvas`의 승인된 08 시안을 구현한다. 작은 TDD 단위로 진행하며 다른 담당자의 공통 UI·셸·API 파일은 수정하지 않는다.

**목표:** 모바일에서 미배치 조명을 `선택 → 맵 탭 → 위치 확인 → 저장` 순서로 배치하고, 편집 정보 패널의 기본 화면을 도구·선택 속성 중심으로 정리한다.

**구조:** 미배치 목록은 배치 요청만 상위 편집기에 전달한다. 캔버스는 기존 카메라 변환으로 탭 좌표를 계산하되, 확인 전에는 store를 수정하지 않는다. 확인은 기존 `placeFixtures`를 호출하고 기존 저장·lease·409 복구를 재사용한다.

**기술:** React, Zustand, Konva, Vitest/Testing Library. 승인 시안: `docs/assets/ux-refresh-2026-09-23/08-mobile-map-placement.png`.

## 후속 통합 검증 (2026-09-24)

- 공통 맵 카메라 단위 회귀 20/20, 맵 배치 Chromium 전체 13/13을 통과했다. 외부 `100%`·맞춤 명령이 진행 중인 핀치나 휠 입력을 덮을 때 가시 조명 목록까지 확정 카메라로 다시 계산하며, 내부 휠 저장은 이어지는 팬을 취소하지 않는다.
- 데스크톱 목록→슬롯 드롭과 대량 배치 성능은 준비된 공통 맵 문서에서 1000개 조명·2000개 슬롯·2000개 맵 요소로 검증했다. 스냅 좌표·되돌리기·저장·층 전환과 320/390px 화면 검증도 포함한다. 20회 준비 시간 테스트만 레거시 CAD 이미지/도형 fixture이므로 공통 맵의 준비 시간 증거로 사용하지 않는다.
- 실제 iOS/Android WebView 터치·safe-area·GPU 성능, 실제 대형 CAD 파일과 Raspberry Pi/ESP32-H2 연동은 이번 Chromium fixture 검증 범위 밖이다. 루트 전체 빌드와 통합 E2E 게이트는 별도로 실행한다.
