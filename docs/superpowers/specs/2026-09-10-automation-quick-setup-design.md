# Automation Quick Setup Design

## 배경

현재 스케줄과 차량 이벤트 설정 dialog는 날짜, 반복, 밝기, 대상의 전체 입력과 긴 조명 목록을 한 화면에 동시에 노출한다. 사용자는 저장 결과를 머릿속에서 조합해야 하고, 대상 목록 때문에 dialog 내부 스크롤이 길어진다. 이벤트 설정은 같은 형태의 목록을 감지 센서와 제어 조명에 두 번 노출한다.

## 목표

- 스케줄은 `언제 → 대상 → 밝기`, 이벤트는 `감지 센서 → 실행 대상 → 동작` 순서로 읽히게 한다.
- 새 규칙의 일반적인 설정은 기본 화면 안에서 끝낸다.
- 월간·연간·사용자 지정 요일, 적용 기간, 규칙 이름, 디밍 사용 여부는 접힌 고급 설정에서 유지한다.
- 긴 대상 목록은 기본 화면에서 제거하고 같은 dialog의 전용 대상 선택 화면에서만 보여준다.
- 하단 요약 문장으로 저장될 핵심 결과를 즉시 확인할 수 있게 한다.
- 기존 API payload, 검증 규칙, 권한 및 생성·수정 동작은 유지한다.

## 화면 구조

### 스케줄 빠른 설정

1. `언제 켤까요?`
   - `매일`, `평일`, `주말`, `한 번` 프리셋을 제공한다.
   - 평일은 `weeklyDays: [1,2,3,4,5]`, 주말은 `[6,7]`로 변환한다.
   - 시작·종료 시각은 한 줄에서 바로 수정한다.
2. `어느 조명을 켤까요?`
   - 현재 선택을 이름과 개수만 포함한 요약 카드로 표시한다.
   - `대상 선택` 또는 `변경`을 누르면 dialog 안의 대상 선택 전용 화면으로 전환한다.
3. `밝기`
   - 30%, 50%, 70%, 100% 프리셋과 range input을 함께 제공한다.
4. `세부 일정 설정`
   - 규칙 이름, 적용 시작·종료일, 전체 반복 종류와 반복별 추가 입력, 디밍 사용 여부를 포함한다.
   - 기존 규칙이 월간·연간 또는 사용자 지정 요일이면 수정 dialog에서 자동으로 펼친다.
5. 하단 요약은 반복, 시간, 대상, 밝기를 한 문장으로 표시한다.

새 스케줄 이름은 기본값 `조명 스케줄`로 시작해 고급 설정을 열지 않아도 저장할 수 있다. 적용 기간은 기존 기본값과 API 계약을 그대로 사용하고 요약에 날짜 범위를 표시해 숨겨진 값을 알 수 있게 한다.

### 이벤트 빠른 설정

1. `감지 센서`와 `실행할 조명`을 위에서 아래로 연결된 요약 카드로 표시한다.
2. 각 카드의 `선택` 또는 `변경` 버튼은 같은 dialog의 전용 fixture 선택 화면으로 전환한다.
3. 감지 센서 선택기는 Gateway 등록 및 차량 감지 capability 검증을 통과한 fixture만 표시한다.
4. 밝기는 50%, 70%, 80%, 100%, 유지 시간은 30초, 1분, 5분 프리셋을 제공한다.
5. 프리셋 외 유지 시간은 `직접 입력`을 선택해 5~1,800초 범위로 입력한다.
6. 규칙 이름과 디밍 사용 여부는 `고급 설정`에 둔다.
7. 하단 요약은 `차량 감지 → 대상 · 밝기 · 유지 시간`으로 표시한다.

## 공통 컴포넌트

- `AutomationPresetGroup`: aria-pressed 기반 단일 선택 버튼 그룹
- `AutomationSelectionCard`: 선택 결과와 개수, 선택/변경 동작
- `AutomationAdvancedSection`: 제어 가능한 접이식 고급 설정
- `AutomationSummaryBar`: 저장 결과의 읽기 전용 요약
- `AutomationTargetPickerView`: 기존 `ControlTargetPicker`를 감싸는 전용 선택 화면

공통 요소는 `apps/web/src/features/control/automation/components`에 유지한다. 실제 목록·필터·최대 선택 수 로직은 기존 `ControlTargetPicker`를 재사용한다.

## 레이아웃 및 접근성

- 1440×900 PC viewport에서 기본 빠른 설정 dialog가 viewport 안에 들어오고 문서 body에 스크롤을 만들지 않아야 한다.
- 대상 선택 화면의 긴 목록만 dialog 내부의 제한된 영역에서 스크롤한다.
- 선택 카드 설명은 두 줄을 넘지 않고 줄임표 처리해 추가 텍스트가 생겨도 footer나 알림 UI를 밀지 않는다.
- 오류가 고급 설정 필드에 있으면 영역을 펼친 후 첫 invalid control에 focus한다.
- 대상 오류이면 대상 선택 화면으로 이동하고 picker group에 focus한다.
- Escape, 닫기, 저장 후 원래 trigger로의 focus 복귀 계약을 유지한다.
- 모바일에서는 기존 full-screen dialog와 최소 44px touch target 계약을 유지한다.

## 비범위

- API, DB, Gateway, firmware 계약 변경
- 새로운 반복 종류나 복합 이벤트 조건 추가
- 대상 선택기의 검색·필터·선택 제한 정책 변경
- 스케줄 또는 이벤트 실행 로직 변경

## 검증 기준

- 단위 테스트에서 프리셋 매핑, 요약 갱신, 고급 설정 자동 펼침, 전용 picker 전환과 기존 payload를 검증한다.
- Chromium E2E에서 1440×900, 1024×768, 390×844, 320×740 레이아웃과 대상 목록 접근성을 검증한다.
- 웹 typecheck와 build를 통과한다.
