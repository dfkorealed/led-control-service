# 운영 UI 추가 주석 14건 — 공통화·사용성 설계

작성일: 2026-10-04. 기준 소스: `32e7a45aa114c19111b252cdcf32a13375099067`.
작업 브랜치: `codex/operations-ui-refinement-20261004`.
상태: 채팅 설계 방향·별도 브랜치 작업은 승인됨. **이 명세의 서면 승인과 구현 계획 승인은 아직 전이며, 제품 구현·검증·병합 완료 문서가 아니다.**
아래 `components/`·`features/` 경로와 컴포넌트 이름은 `apps/web/src`의 기존 소스를 가리킨다. 문서 기준은 `docs/agent-operations.md`와 영향받는 네 메뉴 현황이며, 과거 검증 기록을 새 작업의 통과 증거로 재사용하지 않는다.

## 1. 목적·범위·선택한 접근

현장 운영·시설 관리 담당자가 지도와 목록을 편하게 읽고, 필터와 작업 메뉴를 일관되게 조작하도록 현재 서비스의 기능을 보존하며 정리한다. 근거는 2026-10-04의 새 브라우저 주석 1~14와 사용자가 추가한 공통화 요구다. 이전 22개 주석의 완료 이력, Figma 및 모바일 v4 시안은 별도 자료로 보존하고 재실행하지 않는다.

선택한 접근은 **기존 React Aria·디자인 토큰·지도 기반을 확장한 공통 컴포넌트 + 페이지별 상태 소유**다. 페이지마다 CSS/Popover를 복제하는 접근은 배제하고, 새 UI 라이브러리나 전면 교체는 도입하지 않는다. 공통 기반을 한 담당자가 먼저 수정한 뒤 각 페이지가 소비한다. 표시 방식 공통화가 도메인 계산·권한·명령·편집 저장의 공통화를 뜻하지 않는다.

이번 명세는 UI와 사용자 관찰 계약을 확정한다. 개인 알람 숨김의 정확한 DB/API 식별자·bulk 멱등 기록 보관 규칙은 회수된 Shell/Backend 설계를 바탕으로 **구현 계획에서 확정할 구현 세부 사항**이며, 여기서 임의의 스키마나 엔드포인트를 생성하지 않는다. 새 DDL의 현재 로컬 DB 반영과 실행 중 서비스 적용은 별도 승인 대상이다.

## 3. 공통 FilterPanel 계약

### 표시와 범위

- 검색 입력은 외부에 항상 노출한다. 검색이 없는 화면에 가짜 검색을 추가하지 않는다. 검색 옆의 44px 이상 필터 아이콘 버튼이 상세 Popover를 연다.
- 목록/조회의 기간·상태·분석 단위·정렬·페이지 크기 등 검색 외 조건은 Popover 안에서 조정한다. 현장·표시 맵·제어 유형·명시적 제어/저장 액션·편집 폼 필드는 주요 조작으로 남긴다. 페이지 이동도 필터가 아니다.
- 닫힌 상태에서 활성 조건 수, 의미 있는 조건 요약, 초기화 진입을 제공한다. 활성 수는 기본값과 다른 **검색 외 논리 조건** 수다. 날짜 범위 한 쌍은 1조건이며 기본 페이지 크기는 세지 않는다. 요약은 줄바꿈하며 라벨/선택값을 잘라 숨기지 않는다.
- `필터 초기화`는 상세 조건을 기존 기본값으로 되돌리고 검색은 유지한다. 기존 `전체 초기화` 동작은 검색까지 초기화하는 의미와 콜백을 별도로 보존한다. 두 동작의 라벨과 실제 변경 범위가 일치해야 한다.
- 필터 적용 시점은 기존 소비자의 정책을 유지한다. 열기/닫기 자체로 조회 조건을 변경하거나 새로운 적용/저장 단계를 만들어서는 안 된다. 공통 컴포넌트는 조회/API/URL/도메인 검증을 소유하지 않는다.

### 상태·overlay

기존 `components/ui/FilterPanel.tsx`에 검색·상세 조건·요약·초기화의 표시 슬롯을 확장한다. 자동화의 `AutomationRuleControls`는 기존 조건·건수·페이지 콜백을 전달한다. `CommandHistoryPanel`, `MonitoringLogDrawer`, 통계 분석·보고서 등 조회 소비자는 해당 범위의 값을 계속 소유한다. 통계 개요의 독립 비교/추이 기간을 하나의 전역 기간으로 합치지 않는다.

Popover가 닫히거나 레이아웃이 전환돼도 원문 날짜 초안·오류·검색 debounce·정렬·URL·cursor 정책은 보존한다. 공통 날짜 필드의 부분 입력은 Popover 수명보다 오래 유지되는 기존/부모 draft 경로로 연결한다. 미래 연도·빈 날짜·역전 기간을 자동 보정하거나 이전 정상 값으로 조용히 대체하지 않는다. 기존 유효성 검증 전에는 조회/보고서/CSV 요청을 보내지 않는다.

React Aria와 `overlays/RegisteredPopoverContent.tsx`의 overlay 등록을 재사용한다. 필터→Select/달력의 중첩에서는 Escape/Android Back이 가장 위 overlay부터 닫고, 마지막 필터 닫힘은 연결된 트리거로 초점을 돌린다. pending 때문에 닫을 수 없는 기존 작업은 잠금을 유지한다. 짧은 높이에서는 Popover 본문만 세로 스크롤하며 조건·오류·초기화·닫기가 실제로 도달 가능해야 한다. 포털을 열어 페이지/지도 입력이 동시에 활성화되거나 닫힌 Popover가 Back 우선순위를 차지하면 안 된다.

## 4. 공통 DataGrid·행 작업·자동화 표시

기존 `DataTableShell.tsx`와 `automation/components/AutomationRuleTable.tsx`의 중복 기반을 `components/ui`의 한 DataGrid 표시 계약으로 수렴한다. 기존 export를 사용하는 소비자는 호환 wrapper 또는 같은 작업의 소비자 갱신으로 연결한다. 일반 표에는 HTML table/caption/TH 의미를 유지하며, 이름 때문에 지원하지 않는 ARIA grid 키보드 모델을 선언하지 않는다.

- 헤더 기본값은 중앙 정렬. body는 이름/설명 왼쪽, 수치 오른쪽, 상태/행동 가운데처럼 컬럼별로 별도 지정한다. 긴 이름·날짜·값은 읽을 수 있게 줄바꿈한다.
- 가용 폭은 window breakpoint가 아니라 **해당 목록 컨테이너의 실제 내부 폭**이다. 컬럼별 최소 읽기 폭과 조작 공간을 만족하면 표, 부족하면 라벨이 붙은 카드로 전환한다. resize/200%/사이드 패널이 이 판정을 갱신하되 표시 변경으로 목록 상태를 재생성하지 않는다.
- 문서와 표/카드 내부 모두 가로 스크롤 0이다. `min-width` 고정 표를 `overflow-hidden`으로 잘라 통과시키지 않는다. 명시적으로 삭제한 밝기 컬럼 외의 데이터/상태/행동은 카드에서도 접근 가능해야 한다. 조회 중·빈 성공·오류·재시도·페이지 이동을 보존한다.
- 행의 시각적 아이콘 크기·gap은 줄이되 실제 클릭/터치 영역은 44×44px 이상이며 이웃 영역이 겹치지 않는다. 운영 지도 조명의 기존 48px/지도 도구의 더 큰 hit 계약은 44px로 축소하지 않는다.
- 수정/삭제는 공통 더보기 Popover에 둔다. 행 이름을 포함한 접근 가능한 트리거, 키보드 메뉴 탐색, disabled/pending, 초점 복귀를 제공한다. 삭제는 기존 확인·권한·저장 경계를 거친다. 메뉴를 열거나 선택을 바꾸는 것만으로 삭제/명령을 실행하지 않는다.

스케줄·이벤트 목록은 같은 Grid·작업 메뉴를 소비한다. 스케줄 밝기 컬럼과 두 탭의 상단 요약 패널만 제거한다. 밝기 폼/값/실행 payload, 현장 시간대·반복·다음 실행·동기화 대기/실패·재시도·최근 결과는 행 또는 편집/상세에서 보존한다. 수동 명령 이력을 자동화 전체 실행 이력이라고 재명명하지 않는다.

공통 표의 기존 보고서·운영자 상담 소비자도 회귀 대상이다. 보고서 요청/다운로드/만료 상태·URL/cursor·CSV/PDF 범위, 상담 목록의 데이터/권한은 표시 컴포넌트 변경으로 바꾸지 않는다.

## 5. 공통 지도 기반·읽기/선택/편집 policy

### 재사용 경계

`features/floor-map/FloorMapViewport.tsx`의 viewport·카메라·좌표 변환·제스처와 `FloorScene.tsx`의 운영 도면/마커 표현, `features/map-scene/MapSceneCanvas.tsx`의 공통 렌더러를 유지·확장한다. 편집기의 `FloorEditorCanvas.tsx`는 이미 MapSceneCanvas를 소비하지만 camera/store/쓰기 수명은 별도다. 공유할 수 있는 camera/기하/툴바의 순수 기반과 adapter를 추출하되, 편집기를 운영 viewport로 강제 교체하거나 하나의 store로 합치지 않는다.

| policy | 입력·공통 조작 | 반드시 남길 소유권 |
| --- | --- | --- |
| 모니터링 읽기 | 핀 상세, 이동, 포인터 기준 휠 줌, 핀치, 화면 맞춤 | 상태 조회/정확한 핀 ID/카메라·상세 초점. 문서 쓰기 없음 |
| 제어 선택 | 적격 조명 선택, 빈 영역 추가 선택, 이동/줌 | 권한·대상 방식·단일 Gateway·잠금·대상 snapshot. 선택은 명령이 아님 |
| 설정 편집 | 공통 camera/기하/툴바 + 기존 편집 입력 | 문서 revision·lease·readOnly·undo/redo·draft·레이어·변환·저장 ACK |

제어에서도 modifier 없이 휠 줌을 지원하되 지도 밖 문서 휠을 가로채지 않는다. 포인터 아래 world 좌표를 기준점으로 유지한다. 직접 조명 선택 모드의 빈 지도 왼쪽 드래그는 기존 선택에 적격 영역 대상을 추가한다. Space/가운데 버튼 이동, 층 전체/저장 구역의 이동, 터치의 조명 탭/한 손가락 이동/두 손가락 핀치/400ms 길게 누른 영역 선택은 기존 정책대로다.

8 CSS px 이상 이동은 핀의 단순 클릭 후보를 취소하고 해당 policy의 드래그/이동으로 분기한다. 두 번째 포인터는 클릭/영역 선택 후보를 취소하고 기존 핀치로 전환한다. capture 손실·pointercancel·blur·Escape·층/snapshot/policy 변경·unmount에서는 진행 중 조작/타이머를 정리한다. 줌/이동 후 현재 화면 기하로 정확한 대상을 판정하고 DOM 순서나 선택 상태로 밀집 마커의 이웃을 선택하지 않는다. 취소된 조작은 편집 변경/제어 전송을 만들지 않으며, 정상 드래그 종료 뒤에도 ghost click을 발생시키지 않는다. 운영/편집기의 각 hit 판정은 기존 의미를 보존한다.

### 하단 잘림과 resize

주석 1은 사용자 관측이며 현재 명세에서 원인을 단정하거나 수정 완료로 표시하지 않는다. 승인 후 해당 상태의 실제 viewport·Shell header·맵 frame·도구/범례·로그·nav bounds와 overflow를 재현·기록하고 원인 경계를 수정한다. 충분한 높이에서는 지도가 가용 공간을 채우고, 짧은 높이에서는 기존 최소 도면/도구를 잘라내지 않고 자연 문서 스크롤로 접근한다.

선택/상세 닫힘·요약 이동·필터 표시 변경·resize가 renderer를 재마운트하거나 사용자 zoom/논리 중심/선택/초안을 초기화해서는 안 된다. 최초 fit 및 아직 사용자가 바꾸지 않은 자동 fit과 사용자 camera를 구분하고 기존 `maintainCameraOnResize`·scope별 복원을 재사용한다. 사용자 camera 이후의 fit/reset은 명시적 조작만 수행한다. 전체보기는 같은 지도 수명을 유지하며 닫기·알람센터 접근을 제공한다. native inset·키보드 처리를 중복 추가하지 않는다.

## 6. 최근 결과·inline 상세·명령 안전

수동 제어의 최근 결과는 서버가 확정한 완료 outcome에 한해 `성공 / 일부 성공 / 실패`로 간결하게 표시한다. 전송·조회·처리 중, 응답 유실/시간 초과의 미확정, 실제 상태 확인 필요, 식별자 불일치·보관 종료·저장 복구 실패는 이 3종으로 거짓 확정하지 않고 **별도 상태/경고와 필요한 안전 행동**을 계속 노출한다. 서버 stage/outcome·확인 결과의 기존 의미를 유지하고 단순 건수나 마지막 메시지로 성공을 추정하지 않는다.

`상세 보기`는 최근 결과와 같은 문맥의 inline 영역을 펼친다. 진행 단계·대상별 결과·실패 사유·원본 요청/확인 행동은 이 영역의 세로 스크롤로 읽으며 새 Modal/Drawer를 띄우지 않는다. 기존 전체 명령 이력 조회 Drawer는 별도의 조회 기능으로 유지하고 그 기간·단계·페이지 크기는 §3을 소비한다. 상세 닫기/필터 닫기로 command owner나 polling/복구 수명을 해제하지 않는다.

권한·동일 Gateway·Health/Mesh·전송 중·unknown/보관·복구·로그아웃 잠금을 보존한다. 원본 UUID/canonical payload/서버 확정 targets는 실행 후 picker와 구분한다. 재연결·resize·페이지 복귀·상세 열기·필터 입력은 새 제어 POST를 만들지 않는다. 명시적 확인/안전 재적용도 기존 원본과 사용자 관문을 따른다. 표시를 단순화한다고 retry/timeout/retention 정책을 변경하지 않는다.

## 7. 알람 개별/전체 개인 숨김 — 확정 관찰 계약

- `지우기`는 **현재 인증 계정·선택 현장의 개인 목록에서 숨기기**다. 원본 incident·다른 계정 목록·읽음 기록·장애 해결 상태/수명/revision·운영 activeCount는 변경하지 않는다. 세션 안전 경고까지 숨기는 동작이 아니다.
- 개인 표시 목록과 해당 목록의 미읽음 badge 집계에서만 제외하고 서버에 영속한다. 기존 읽음 receipt는 행 존재 자체가 읽음을 뜻하며 readAt이 필수이므로, 숨김을 이 receipt 생성으로 표현하지 않는다. 숨김은 읽음과 독립된 모델/관찰 경계다.
- 개별 지우기는 정확한 incident 하나를 대상으로 한다. `전체 지우기`는 페이지/목록 필터와 무관하게 **현재 계정·선택 현장에서 아직 개인 목록에 표시되는 모든 알람**을 대상으로 하며 확인 안내에 이 범위를 명시한다. 다른 현장은 포함하지 않는다.
- 서버는 인가/필요 잠금 뒤 한 SQL의 MVCC snapshot에서 대상 ID 집합을 고정한다. 클라이언트에 로드된 페이지나 단순 `createdAt <= 시각` 조건으로 전체 범위/동시·늦은 commit 안전성을 대체하지 않는다.
- 진행 중 도착한 새 알람은 그 고정 집합에 없으므로 남는다. 같은 요청키의 응답 유실 후 재시도는 **원래 고정 집합**을 재사용하며 새 snapshot으로 새 알람을 숨기지 않는다. 같은 요청의 중복은 중복 효과를 만들지 않는다.
- 같은 active incident의 업데이트/재조회는 숨김을 유지한다. 복구 뒤 새 ID로 재발한 incident는 새 알람으로 표시한다. 숨김을 원본 해결·재발 억제 정책으로 사용하지 않는다.
- 숨김 mutation은 읽음 값을 바꾸지 않는다. 별도로 존재하는 '화면에 실제 보인 항목만 읽음' 정책은 유지하므로 두 동작의 검증 시점을 분리한다. 필터 밖/화면 밖 알람을 숨김 때문에 읽음 처리하지 않는다.
- pending 중 중복 조작을 막고 실패/응답 불명은 완료라고 표시하지 않는다. 동일 요청의 안전한 확인/재시도와 목록/badge 재조회로 복구한다. 계정/현장 전환 뒤 늦은 응답은 이전 scope에만 귀속하며 새 화면을 비우지 않는다.

이 명세는 위 동작만 확정한다. Backend/Shell은 구현 계획에서 독립 개인 숨김 모델, 인가·멱등/집합 보관·원자성, API 요청/응답 및 migration 식별자를 확정한다. 원본/읽음/장애 불변과 재시도 집합 보존을 못 지키는 설계는 구현 관문을 통과할 수 없다.

## 8. 현장 전체 밴드·설정 계정·로그아웃

모니터링의 현장 전체 집계는 Shell header의 독립 compact slot/band로 이동한다. `현장 전체`와 현재 현장 이름을 명시하고 비인터랙티브 집계로 표현한다. 선택 맵 요약은 맵 근처에서 맵 이름/필터 선택을 표시하므로 두 집계의 스타일·라벨·역할이 같아 보이지 않아야 한다. 현재 dashboard의 확정 집계를 소비하고 null/로딩/오류를 0으로 만들거나 보이는 핀 수로 전체 집계를 추정하지 않는다.

헤더 slot은 모니터링 경로의 현재 계정·선택 현장에 바인딩한다. 이전 페이지/현장의 등록은 정리하고 늦은 값은 새 scope에 쓰지 않는다. 공통 현장 selector는 계속 Shell 소유이며 허용 현장·URL/query/hash·dirty guard를 유지한다. 긴 이름/200%에서 헤더 높이를 유연하게 늘리고 필수 selector/알람 버튼을 잘라 단일 행을 강제하지 않는다. 전체보기에서 header가 숨으면 필요한 현장 문맥/센터 접근을 도구에 남긴다.

일반 고객 헤더의 로그아웃 버튼은 설정의 공통 계정 영역으로 옮긴다. 현재 admin 전용 보안 카드 안에만 넣지 않고 viewer를 포함한 모든 고객 역할, 현장 없음·설치 pending·오류에도 계정 표시/로그아웃이 접근 가능해야 한다. 관리/보안 기능의 기존 권한은 풀지 않는다. lazy 설정 실패 때는 eager recovery 계정 탈출 경로를 제공한다. 운영자 Shell의 별도 인증 UI를 이번 이동으로 임의 변경하지 않는다.

로그아웃 handler/state/명령 세션 차단/cache 정리는 `CustomerShell`의 단일 owner를 유지하고 설정은 callback·pending·오류·focus target을 소비한다. 미저장 초안 확인 취소는 초안/현장을 보존하고, 로그아웃 실패는 계정·오류/재시도 및 연결된 설정 트리거로의 초점을 유지한다. 진행 중 physical 명령이 취소됐다고 안내하지 않는다. 인증 실패/앱 복구의 기존 eager 탈출과 일반 로그아웃을 혼동하지 않는다.

## 10. 소유 순서·문서·다음 승인

총괄은 승인/상태/구현 계획을 집계하고 단독 파일 소유권을 배정한다. 공통 UI 표시 기반, 공통 지도 기반, Shell/개인 알람 Backend 계약은 각 경계의 단독 작성자가 먼저 확정한다. 같은 파일/계약을 병렬로 수정하지 않는다. 이후 모니터링·제어·통계·설정 담당이 승인된 공통 계약을 소비하고, 영향을 받는 `docs/menus/{monitoring,control,statistics,settings}.md` 및 운영자 소비 변경 시 `operator.md`를 코드와 같은 작업에서 갱신한다. DB 변경 담당은 `docs/database-schema.md`를 갱신한다.

이 턴의 작성권은 이 명세 한 파일뿐이다. root 상태/계획·메뉴·DB 문서는 이 문서 커밋에 포함하지 않는다. **서면 명세 승인 → 구현 계획/정확한 파일 소유·DB/API 세부 확정 및 승인 → 구현/검증 → 통합 검토 → 사용자 요청에 따른 별도 브랜치 병합** 순서로 진행한다. 현재 서버/DB 적용과 새 DDL 적용은 승인 범위를 별도로 확인한다.

자체 검토: 주석 1~14 누락 없음, 표현 제거와 기능/안전 제거 구분. 이동 임계값의 클릭 취소/드래그 전환과 최초 자동 fit/사용자 camera 보존을 명확히 분리해 문구의 모순을 보완했다. scope·초안·명령·알람 snapshot 계약의 미해결 모순 및 사용자 동작의 미결정 사항 없음. DB/API 식별자·멱등 기록 보관의 계획 단계 확정은 명시적 후속 관문이며 이미 구현됐다는 의미가 아니다.
