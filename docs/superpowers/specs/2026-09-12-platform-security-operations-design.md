# 플랫폼 계정 보안 운영 설계

기준일: 2026-09-12

## 목적

operator와 admin 계정에 TOTP 기반 2단계 인증을 제공하고, 모든 계정이 자신의 로그인 세션을 조회·종료할 수 있게 한다. 로그인 공격은 Redis 기반의 IP·계정·고객사/IP 제한으로 차단하며 제한 저장소가 동작하지 않으면 인증을 허용하지 않는다.

## 인증 흐름

- MFA가 꺼진 계정은 아이디·비밀번호 검증 후 바로 세션을 발급한다.
- MFA가 켜진 operator/admin은 비밀번호 검증 후 짧은 수명의 일회성 MFA 챌린지만 발급한다. TOTP 또는 복구 코드를 추가 검증해야 세션이 생성된다.
- 챌린지는 Redis에 암호화된 임시 데이터로 저장하고 계정, 접속 IP, User-Agent, 자동 로그인 선택과 결속한다.
- 로그인 제한은 IP, 정규화된 로그인 아이디, 확인 가능한 고객사와 IP 조합을 각각 계산한다. Redis 오류 시 `503`으로 닫고, 제한 초과는 동일한 `429` 응답으로 처리한다.
- 클라이언트 IP는 Express가 계산한 `request.ip`만 사용한다. 임의의 `X-Forwarded-For` 헤더를 직접 신뢰하지 않는다.

## MFA

- 대상 역할은 operator와 admin이다. viewer는 MFA 등록 API를 사용할 수 없다.
- 등록 시작 시 Base32 비밀키와 `otpauth://` URI를 한 번 표시한다. 확인 전 비밀키는 Redis에 암호화해 제한 시간 동안만 보관한다.
- 등록 확인 시 TOTP를 검증하고 암호화된 비밀키와 복구 코드 해시만 PostgreSQL에 저장한다. 복구 코드 원문은 이 응답에서만 반환한다.
- 복구 코드는 한 번만 사용할 수 있으며 사용 시 트랜잭션 안에서 원자적으로 제거한다.
- MFA 해제는 현재 비밀번호와 현재 TOTP 또는 복구 코드를 함께 요구한다.
- 비밀키 암호화는 `MFA_ENCRYPTION_KEY`의 32바이트 키와 AES-256-GCM을 사용한다. 키가 없거나 잘못되면 MFA 경로를 허용하지 않는다.

## 세션

- 사용자는 현재 계정의 활성 세션 목록에서 생성 시각, 만료 시각, IP, 브라우저 정보를 확인한다.
- 개별 세션 종료와 현재 세션을 제외한 전체 종료를 제공한다. 현재 세션을 종료하면 쿠키도 삭제한다.
- 비밀번호 변경과 MFA 등록·해제는 모든 기존 세션을 폐기하고 현재 요청에만 새 토큰을 발급한다. 필수 비밀번호 변경 흐름도 새 쿠키를 받아 계속 진행한다.
- viewer의 제어/조회 권한, 계정 활성 상태, 운영자가 초기화한 비밀번호가 바뀌면 대상 사용자의 기존 세션을 모두 폐기한다.

## 감사 기록

- 로그인 성공·실패·제한·제한 저장소 장애, MFA 등록·해제·복구 코드 사용, 세션 종료를 `AuditLog`에 남긴다.
- 비밀번호, TOTP 비밀키, TOTP 코드, 복구 코드, 세션 토큰은 감사 metadata에 기록하지 않는다.
- 보안 상태 변경과 성공 감사 기록은 같은 PostgreSQL 트랜잭션으로 커밋한다.

## UI

- 로그인 화면은 비밀번호 검증 뒤 MFA 코드 입력 단계로 전환되며 일반 코드와 복구 코드를 선택할 수 있다.
- admin 설정의 보안 탭은 비밀번호 변경, MFA 상태/등록/해제, 활성 세션 목록을 실제 API로 표시한다.
- operator 화면에는 기존 현장 관리자 관리와 분리된 계정 보안 경로를 추가한다.
- 비동기 상태, 오류, 성공 안내는 `aria-live`와 명시적 label을 사용하고 키보드만으로 조작할 수 있어야 한다.

## 제외

- SMS·이메일 OTP, WebAuthn, 강제 MFA 정책, 운영 배포와 사용자 DB migration은 이번 범위에서 제외한다.
- 검증은 일회용 PostgreSQL·Redis와 소프트웨어 브라우저 환경만 사용한다.
