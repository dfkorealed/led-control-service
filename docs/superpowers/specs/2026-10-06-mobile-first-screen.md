# 모바일 첫 화면·공통 헤더 적용 명세

2026-10-06 사용자가 브라우저 A안 적용·별도 브랜치 작업 후 로컬 병합을 승인했다. 최신 메인의 기존 탭·버튼·입력 크기를 우선하며 시안의 새 크기/가상 컨트롤을 그대로 복제하지 않는다. 시안 검토 기록은 상태판의 2026-10-04 항목과 ignored `.local/mobile-first-screen-preview/design-brief.md`에 있다.

## 범위와 현재 기준

- 작업 브랜치 `codex/mobile-first-screen-20261004`, 격리 checkout `.worktrees/mobile-webview-audit`. 최신 메인 `f74fc94f`를 `efd3820a`에서 먼저 통합했다. 이전 iOS 입력 가시성 보완과 최신 필터/Grid/도면/알람 지우기 기능을 모두 보존했다.
- 동일 웹의 기존 compact `<760px`를 모바일 범위로 한다. Android/iOS WebView와 모바일 브라우저가 같은 화면을 소비한다. 새 라이브러리·API·DB·네이티브 셸 변경은 필요하지 않다.
- 공통 현장 선택과 설정의 eager 내 계정/로그아웃 영역은 이미 최신 메인에 있다. 기존 URL·권한·미저장 변경 가드와 로그아웃 controller를 유지하고 표현만 필요한 만큼 조정한다.
- 기존 탭 종류, 높이, 글자 크기, 버튼·SelectBox·카드 토큰을 유지한다. 별도의 시안용 통계 Select 탭을 제품에 추가하지 않는다. 모바일 조작 영역은 기존 최소 44px를 유지한다.
- 정상 100% 글자 크기의 320×568/390×844/430×932에서 첫 진입 scroll0에 모니터링·수동 제어의 실제 도면, 통계 개요 비교 그래프·분석 순위가 보인다. 그래픽의 유효 표시 높이는 320에서 최소120px, 390/430에서 최소240px를 목표/검증 기준으로 한다. 큰 글자·오류·긴 이름은 자연 스크롤을 허용하며 잘라서 맞추지 않는다. 실제 현장 전체를 한 화면에 항상 넣는다는 보장은 아니다. 도면의 표시 높이는 로드된 floor surface를 렌더하는 interactive map viewport와 viewport/하단 메뉴/clip의 교차를 측정한다. 카드 wrapper·빈 placeholder는 제외한다. 원본 CAD 비율에 따른 이미지 픽셀 자체 높이와 여백은 별도로 기록하며 강제 확대나 fixture 비율 변경으로 기준을 맞추지 않는다.

## 알림과 공통 헤더

- 모바일 상단 toast를 시각적으로 표시하지 않는다. desktop 기존 toast는 유지한다. timer가 사라져 큐가 쌓이거나 breakpoint 변경 시 지난 toast가 되살아나지 않게 한다. 화면 읽기 알림은 유지한다.
- 기존 서버 현장 알람 미읽음 수·읽음 저장·개인 지우기·전체 지우기·원본 장애 분리 계약을 그대로 유지한다. 서버 알람과 별도로 기존 toast로 전달하던 성공/경고/오류를 같은 알람센터의 `최근 알림`에서 읽는다.
- 모바일 배지는 서버 미읽음 현장 알람과 세션 미읽음 최근 알림의 합계다. 두 종류의 알림 수이며 고유 장애 수가 아니다. 서버 개수를 확인할 수 없을 때 임의의 정상0을 표시하지 않는다. desktop 기존 배지 의미는 보존한다.
- 최근 알림은 세션 메모리에 최대50개 보관한다. 같은 상태 fingerprint polling은 새 알림이 아니며 새 상태·변경 내용·별도 작업 알림은 읽지 않음으로 표시한다. toast 종료는 최근 알림 읽음/삭제가 아니다. 읽음은 장애 해결·명령 실행·지우기가 아니다.
- principal/허가된 site scope 변경 시 최근 알림과 미읽음을 격리한다. 이전 scope의 늦은 callback이 새 scope를 오염시키지 않는다. 새 문서·로그아웃·다른 기기와 최근 알림 읽음을 동기화하지 않으며 저장소·새 서버 테이블을 만들지 않는다.
- compact 헤더는 현장 선택과 알람센터 한 행을 우선한다. 중복 메뉴 제목과 펼친 현장 전체 집계로 도면을 밀지 않는다. 현장 전체 집계는 명시적인 펼침/상세로 계속 확인 가능하게 한다. 긴 이름의 전체 접근 가능한 이름과 기존 선택/실패/대기 상태를 유지한다.
- 전체보기에서 헤더가 숨겨져도 같은 알람센터에 접근할 수 있다. 접근 수단은 기존 전체보기 종료·지도 도구를 가리지 않아야 한다. 입력 검증·로그인 복구·제어 확인·진행/불확정 피드백을 배지로만 숨기지 않는다.

## 모니터링·제어

- 모니터링: 현장 전체는 접어서 조회, 맵 선택·선택 맵 핵심 상태·실제 도면이 우선이다. 검색/수동 확인/운영 기록은 기존 drawer/도구를 재사용하며 접근성과 데이터 의미를 유지한다.
- 제어: 기존 수동/스케줄/이벤트 탭을 유지한다. 수동은 맵 선택·선택 요약·도면이 우선이며 실행 설정은 명시적으로 연다. 제어 실행 owner/원본 UUID/대상 snapshot/복구 기록은 drawer 바깥에서 유지한다. 닫기·resize·현장 변경·app 복귀가 새 명령 POST를 재전송하지 않는다. 진행/불확정/실패 복구는 계속 확인 가능하다.
- 데이터 집계, 실제 0과 모름, stale/오류, 선택/카메라/필터, 전체보기, 조명 상세, 최신 명령 결과와 명령 이력을 보존한다. 레이아웃 변경이 hardware refresh를 자동 실행하지 않는다.

## 통계·설정

- 기존 통계 밑줄형 탭과 날짜/필터 컴포넌트를 유지한다. 개요는 기간·핵심 요약·기존 비교 그래프, 분석은 조건 요약·순위 막대, 리포트는 최근 이력/파일 작업을 우선한다. 추가 KPI·표·히트맵/조건은 명시적 상세 또는 그래프 이후에 배치한다.
- 추정/정격 비교 기준·partial/null/no_data·수집 공백을 보존한다. 기간별 의미·현장 scope·응답 일치·날짜 초안/조회 가드·CSV/PDF 취소와 원본 파일 ID 계약을 변경하지 않는다.
- 설정의 공통 내 계정/로그아웃은 모든 customer role·설치 대기·lazy 실패에서 접근 가능하다. 이미 존재하는 구현을 재사용하며 기존 설정 관리 권한을 바꾸지 않는다.

## 검증·병합

각 기능의 변경 전 재현/필수 회귀를 확인하고 해당 단위·관련 브라우저 시나리오를 실행한다. 전체 Web test/typecheck/build/UI policy와 기존 Mobile 입력 보완 회귀를 최종 한 번 확인한다. 3개 모바일 크기와 desktop 회귀·디자이너 실제 캡처 검토·독립 코드 검토 뒤 `codex/mvp1-cloud-web`에 로컬 병합한다. 원격 push·DB 변경·장비/HIL·스토어 배포는 범위가 아니다. 기존 메인의 Gateway timeout과 production audit 한계는 해당 코드 변경 없이 이 작업의 통과로 바꾸지 않는다. 네 메뉴 문서를 코드와 같은 작업에 갱신한다.
