# ATLAS 목업의 실제 고객 서비스 UI 적용 명세

기준일: 2026-10-07

상태: 사용자 서면 명세 검토 대기. 제품 구현·제품 검증·병합은 아직 시작하지 않았다.

## 1. 목적과 승인 기준

승인된 ATLAS compact 목업과 브라우저 수정 의견을 실제 React 고객 서비스에 적용한다. 공통 컴포넌트와 디자인 역할을 먼저 통일하고, 모니터링·제어·통계·설정 담당 에이전트가 이를 소비한다. 기존 API, 권한, 명령 실행·복구, 실제 도면과 데이터의 의미는 유지한다.

- 최신 추가 요구: 모바일 헤더에도 실제 킨다 로고를 표시하고 현장 선택의 너비를 줄인다.
- 공통 도면 상태는 큰 카드 네 칸이 아니라 기존 인라인 배치에서 글자만 조금 키운다. 모니터링과 수동 제어에 동일하게 적용한다.
- 수동 제어의 이동·개별 선택·영역 선택 도구는 도면 패널 상단에 붙인다.
- PC 수동 제어는 화면 바깥 세로 스크롤 없이 도면·밝기 적용·이력에 접근한다. 모바일은 자연스러운 세로 스크롤을 유지한다.
- 실제 구현은 별도 브랜치에서 진행하고 검증 후 기존 개발 브랜치에 로컬 병합한다. 원격 push, PR, 배포, DB 변경, 실장비 조작은 포함하지 않는다.

디자인 기준은 [보존된 목업](../../assets/atlas-ui-refresh-2026-10-07/README.md)이다. 마지막 모바일 로고 의견은 이 명세의 추가 기준이며 보존된 목업에는 아직 반영되지 않았다. 목업은 디자인 참고 자료이며 제품 구현·데이터·안전정책의 정본이 아니다.

## 2. 적용 범위와 선택한 접근

### 선택: 기존 제품 구조 위에 공통 표현 계층 적용

React Aria 기반 입력·버튼·오버레이, Tailwind semantic token, 기존 기능 모듈을 유지한다. 공통 UI를 먼저 확장한 뒤 네 메뉴와 그 하위 화면을 같은 표현 계약으로 전환한다. 페이지별 별도 버튼·카드·필터·테이블을 만들지 않는다.

다른 접근의 비용은 다음과 같다.

1. 목업 HTML/CSS/전역 상태를 직접 이식하면 React Aria 접근성, 실제 API 수명, 명령 복구와 정책 검사를 다시 구현해야 한다.
2. 페이지별 스타일만 바꾸면 중복과 디자인 차이가 남고 공유 지도·필터 소비자 사이의 회귀를 발견하기 어렵다.

이 작업은 공통 구조와 소비자 인터페이스를 함께 바꾸는 아키텍처 변경으로 취급한다. 승인된 목업 방향은 명세 작성의 근거이고, 서면 명세와 이후 실행 계획의 검토를 제품 구현 승인으로 대체하지 않는다.

### 범위 밖

- API·공유 스키마·DB·MQTT·Gateway·펌웨어 계약 변경
- 공개 랜딩, 로그인, 운영자 UI의 신규 디자인
- 목업의 가상 데이터, 성공/실패 시나리오 선택, 가상 Gateway, 가짜 SVG 도면, 예시 초기화 기능의 제품 이식
- 새 센서 이벤트, 새 통계 집계 API, 가짜 보고서 완료·다운로드
- 기존 기능을 감추거나 삭제해서 화면 높이를 맞추는 변경

### 테마 기본 범위

이전의 다크 모드 후속 적용 결정을 기본으로 **이번에는 라이트 UI와 향후 테마 확장을 위한 semantic 역할 구조만 적용**한다. 실제 제품에 아직 테마 전환 기반이 없으므로 목업의 다크 모드 버튼을 동작하지 않는 제품 버튼으로 넣지 않는다. 별도로 제시한 다크 모드 범위 질문에서 이번 전환 구현을 선택하면 이 명세를 수정하고 다시 검토한다.

## 3. 디자인 시스템과 공통 UI 계약

### 토큰과 적용 경계

`apps/web/src/styles/theme.css`의 단일 `@theme static`을 계속 정본으로 사용한다. 고객 shell에 customer appearance 경계를 두고 공통 컴포넌트의 고객 표현과 차트·지도 색상 adapter가 같은 역할을 사용하게 한다. 고객용 역할을 추가하되 기본 공통 표현과 brand·landing 역할은 보존하여 로그인·운영자·공개 화면을 의도치 않게 바꾸지 않는다.

| 고객 역할 | ATLAS 라이트 기준 | 비고 |
| --- | --- | --- |
| 화면 / 패널 | `#F4F7FB` / 흰색 | inset·선택·피드백은 별도 의미 역할 |
| 본문 / 기본 경계 | `#152C43` / `#D8E1EC` | 비활성·보조·강한 경계는 분리 |
| 주요 동작 | `#245FE8` | foreground·hover·focus를 독립 역할로 매핑 |
| 정상 / 주의 / 오류 | `#187445` / `#946000` / `#B4233C` | 텍스트·아이콘·상태 라벨 병행 |

간격은 기존 승인 스케일을 재사용한다. 반복 section·panel 간격, typography, control 반경과 focus ring은 공통 컴포넌트가 소유한다. 목업의 숫자와 색상을 소비자에 literal로 복사하지 않는다. 새로운 layout 치수와 typography 역할은 소비 목적을 문서화해 승인 토큰으로 추가한다.

기존 정책은 승인 앵커 `7b2617b173618d376e7b3a90ec31e1392c3b7bc0`의 375개 역할을 고정한다. 변경 순서는 역할 매핑 검토 → 토큰 전용 커밋 → 별도 정책 앵커 회전 검토·문서 갱신 → 전체 정책 검사 → 공통 컴포넌트 → 메뉴 소비자다. 중간 토큰 커밋의 예상 정책 실패를 전체 통과로 표시하지 않는다. 빈 baseline, Git object 누락 시 차단, 금지 literal·selector·native form 규칙은 유지한다.

### 공통 요소

| 메뉴 탭·필터·목록 | UnderlineNavigation, FilterPanel, DataGrid, DrawerDialog/Dialog/Popover를 유지한다. 공통 spacing·상태·반응형 표현을 적용하고 메뉴마다 가짜 필터 API를 만들지 않는다. |
| 도면 상태 | 공통 인라인 집계 표현. 기본 라벨 14px·수치 16px. 큰 카드나 별도 세로 행을 예약하지 않는다. 작은 화면에서는 패널 chrome 내부 줄바꿈을 허용하되 값과 라벨을 분리하지 않는다. |
| 도면 chrome | 제목/인라인 집계/선택 도구/카메라 footer의 표현을 공유한다. 데이터·선택·제어 명령은 소유하지 않는다. |

기존 모바일 utility 경계인 `max-compact`의 **760px 미만**을 따른다. 목업의 680/700px 분기나 legacy CSS의 760px 포함 조건을 섞지 않는다. 759.5/760/760.5px 경계를 검증한다. 모든 조작은 최소 44px hit 영역을 유지하며 지도에 이미 더 큰 hit 영역이 있으면 줄이지 않는다.

sidebar의 영문 부제와 중복 현장 안내는 정리하되 헤더의 실제 현장 선택·집계와 권한·운영 경고는 보존한다. 접힌 rail에는 메뉴 이름을 알 수 있는 접근성 이름과 tooltip을 제공한다. 목업의 가상 Gateway 현장 카드는 제품에 추가하지 않는다.

### 지도 도구와 높이

공유 지도 구현자는 FloorMapViewport와 SpatialTargetSelector의 소비자를 먼저 조사한다. 수동 제어에서는 사용자가 선택한 pan/select/area 모드가 실제 gesture 정책에 반영되도록 명시적 계약을 둔다. 다른 등록·스케줄·이벤트·구역 편집 소비자의 기존 interactionPolicy를 무조건 바꾸지 않는다.

PC 수동 제어는 shell 아래 남는 높이를 flex/grid로 배분한다. 외부 문서 세로 스크롤은 없고 도면/우측 제어/하단 한 줄 이력이 배치된다. 결과·경고·복구 내용은 제어 패널의 내부 스크롤 영역에 놓고 실행 버튼과 복구 동작을 끝까지 접근할 수 있게 한다.

- 표준 PC 검증: 1304×1229, 1440×900, 1024×768 및 760px 경계의 768px 높이.
- 짧은 PC 1024×600: 실제 지도 canvas 최소 240px과 모든 안전 안내를 보존한다. 높이가 부족하면 **내부 workspace 스크롤**로 전환하여 전체 기능에 접근한다. 외부 문서 스크롤 차단만으로 내용을 잘라내지 않는다.
- 모바일: 자연 세로 스크롤, 항상 노출된 지도 도구와 밝기 설정·적용 버튼. 도구/실행 설정을 펼쳐야만 접근하는 별도 disclosure는 제거한다.
- 크기 변경·지도 전체 보기·복귀 시 camera 상태, 좌표 변환, 선택, focus, resize cleanup을 보존한다.

## 4. 메뉴별 적용

### 모니터링

- 불필요한 설명·도면 사용 안내를 제거하고 제목, 실제 마지막 갱신 시각, 새로고침, 층 선택·검색/상세·목록을 명확히 배치한다.
- 도면 상태는 MonitoringSummary에서 공통 인라인 표현을 소비한다. 서버 `floor.summary`를 사용하며 로딩된 pin/fixture 페이지를 전체 집계로 사용하지 않는다. 누락·알 수 없음은 `—`, 실제 0은 `0`이다.
- 마지막 갱신은 서버 snapshot과 현장 시간대를 사용한다. 클릭 시각을 성공한 갱신 시각으로 만들지 않는다. 기존 장치 상태 갱신 job 완료와 관련 query refetch, 반복 클릭 잠금, 층 변경/unmount 취소, 부분 성공을 보존한다.
- 최근 활동은 공통 5초 ticker와 전체 보기로 표현한다. 실제 API의 날짜·개수·cursor 계약, draft 날짜 검증, 보존 기간, scope 초기화, 400 cursor 복구를 유지한다. API에 없는 검색/상태 필터는 제공하지 않는다.
- 선택 상세 Popover, 정확한 fixture ID, 위치 강조와 map camera 기억을 유지한다. 현장 전체 집계와 현재 층 집계를 혼동하지 않는다.

### 제어

- 수동 제어·스케줄·이벤트·그룹/구역의 공통 탭 표현을 적용한다. 기존 `mode=manual|schedule|event` 링크와 siteId/query/hash는 보존하고 그룹/구역은 frontend mode로 추가한다. 권한은 기존 관리/읽기/제어 capability를 따른다.
- 그룹/구역 탭은 기존 FixtureGroupDialog와 map editor의 실제 조회·CRUD 기능을 재사용한다. 별도의 가상 구역 저장소나 새 backend 계약을 만들지 않는다. 기존 dialog를 호출하는 다른 경로도 보존한다.
- 수동 제어의 중복 도면 제목·설명·range 끝 라벨·정적인 실행 안내·빈 결과 영역을 정리한다. 도구는 도면 상단에 붙이고 상태는 인라인으로 통일한다. 우측 제어 패널 시작선을 도면에 맞춘다.
- 밝기 raw 입력의 빈 값·소수·범위 오류를 유지한다. Apply 차단, blur/Enter 시 마지막 유효 값 복원과 별도 적용 요구를 유지한다. 같은 blur/click으로 명령이 발송되거나 목업처럼 값을 임의 clamp하지 않는다.
- **선택 전체 차단 정책을 유지한다.** 누락·미배치·다중 Gateway·부적격 대상이 섞이면 기존 정책대로 실행을 차단한다. 목업의 오프라인 제외 후 나머지 실행 방식으로 변경하지 않는다.
- 처음 아무 명령도 없는 빈 결과 자리만 제거한다. 제출·진행·불명확·불일치·404/410·보존 만료·storage 실패·실제 상태 확인·안전 재적용·확인 필요 사례는 숨기거나 unmount하지 않는다.
- 명령 owner, frozen UUID/canonical payload/ACK 대상, 사용자·현장·generation 격리, 복구 저장소·로그아웃 잠금, A→B→A 늦은 응답 격리, remount 복구를 보존한다. 안전 재적용은 현재 선택이 아닌 원래 대상과 밝기를 사용한다.
- 제어 이력은 실제 recent query를 공통 ticker로 표현한다. 조회 개수 증가는 기존 endpoint의 지원 계약 안에서만 한다. 전체 이력 검색 debounce·날짜·단계·cursor·UUID 상세·확인 필요 사례 연결은 유지한다.
- 스케줄과 실제 **차량 이벤트**의 필드·시간대·활성화/비활성화·동기화/대기/실패/재시도·목록 정렬을 유지한다. 목업의 조도/움직임 센서 이벤트로 바꾸지 않는다.

### 통계

- 개요·분석·보고서 탭과 큰 지표/비교 그래프/순위/파일 우선 배치를 공통 스타일로 통일한다. 기존 route/siteId/query/hash와 기간 선택을 유지한다.
- 오늘·이번 달·연간 계산, 완료 기간 비교와 진행 기간 예상은 각각의 실제 의미를 유지한다. 서로 다른 period 응답을 섞지 않는다.
- 운영 인사이트의 중복 이동 CTA 대신 API가 실제 제공하는 **알려진 상태시간, 수집 공백, 최근 집계, 기준 조명 수** 등 데이터 품질 정보를 사용한다.
- API에 없는 표본 수·최근 수집 시각·층별 절감 기여도는 만들지 않는다. generatedAt을 수집 시각으로, 사용량 순위를 절감 순위로 바꾸지 않는다.
- 추정값/실측 아님, null/no_data와 수집된 0, 그래프 공백, 음수 절감, coverageRate, 독립 오류·재시도를 유지한다. 실제 조명·층·그룹 순위, 선택 상세·heatmap은 기존 계산을 사용한다.
- 보고서 실제 job polling, PDF/CSV, signed URL·만료·실패·다운로드·재생성과 필터/정렬을 보존한다. 가짜 즉시 완료나 샘플 다운로드로 바꾸지 않는다.

### 설정

- 제목은 `설정`으로 단순화하고 영문 eyebrow·일반 설명·화면 환경 카드·점 세 개 장식 아이콘을 제거한다. 실제 현장 관리·사용자·조명 등록·도면·계정 보안 카드의 아이콘·이름·요약을 통일한다.
- 카드는 capability에 따라 노출한다. 사용자 수는 관리 권한이 있을 때만 실제 query로 읽고, MFA·알 수 없는 상태는 조회 전까지 꺼짐으로 표시하지 않는다. `mapConfigured`를 도면 설정의 정본으로 사용한다.
- 모바일 settings 메뉴 탭은 숨기고 모든 하위 설정 화면에 공통 `설정으로 돌아가기`를 한 번만 제공한다. 직접 링크·뒤로 가기·focus와 siteId를 보존한다.
- 현장/층/전력/구역/보관·복원/요금 단가, 사용자 loginId·read/control·active/disabled·100명 한도·일회용 비밀번호·expectedUpdatedAt·정확한 삭제 확인을 유지한다.
- 조명 등록, 설치 pending/setup, claim/provisioning, CAD·도면 편집 lease/revision/undo/draft/storage/dirty navigation/save ACK, MFA·사용자 수명 격리를 유지한다. 목업 사용자 email/admin 옵션이나 가짜 상태를 이식하지 않는다.
