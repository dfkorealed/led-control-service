# 킨다 랜딩 설득력·동작 개편 설계

기준일: 2026-09-26

## 목적

기존 공개 랜딩이 기능 이름을 나열하는 수준에 머물러 있다는 사용자 피드백을 반영한다. 시설·주차장 운영 담당자와 시공·유통 파트너가 각각 자신의 업무 문제, 킨다에서 할 수 있는 일, 상담을 통해 확인할 다음 단계를 이해하도록 만든다. 두 고객군의 비중은 비슷하게 유지한다.

## 사실성과 표현 범위

- 공개 첫 화면은 실제 고객 데이터나 실사용 성과를 요구하지 않는다. 확인되지 않은 절감률·가용률·고객 로고·도입 사례·알림/SLA·실시간 push를 주장하지 않는다.
- 대시보드는 클릭 가능한 **구성 예시**로서 모니터링·제어·기록의 흐름을 보여준다. 조명 제어 API를 호출하지 않는다. 선택 상태와 전환은 예시 화면 안에서만 변한다.
- 사용자가 지목한 대시보드 상단의 `제품 화면 예시` 및 `현장 · 도면 · 조명을 한 화면에서` 문구를 제거한다. 예시를 실제 운영 데이터로 오해하지 않도록 하단의 짧은 설명과 figure의 접근 가능한 이름은 유지한다.
- 실제 제품 기능에 근거한 표현만 사용한다: 현장/층/도면 기반 위치 확인, 연결/최근 상태 확인, 개별·그룹 점등/밝기 제어, 일정 운영, 제어 처리 이력, 기간별 **상태 기반 추정** 전력, 현장·Gateway·조명 등록, 검토 후 적용하는 CAD 도면 배치. `실시간`, 자동 CAD 조명 등록, 절감 보장, 장애 알림/SLA는 주장하지 않는다.

## 정보 구조

1. **첫 화면:** 작업 중심 제목과 한 문장의 가치 제안, 상담 CTA, 큰 관제 화면. 제목은 추상적인 `간단하게`보다 `위치 파악 → 제어 → 확인`을 직접 말한다.
2. **문제에서 결과로:** 세 가지 업무 질문을 순서대로 다룬다. `어디에 있는가?`에서는 도면/상태, `무엇을 바꿀까?`에서는 개별·그룹·일정 제어, `어떻게 확인할까?`에서는 명령 이력과 추정 전력을 설명한다. 각 설명에는 해당 제품 예시가 맞물린다.
3. **고객군별 이유:** 시설 운영과 시공·유통 각각에서 업무 시작점, 킨다에서 이어지는 행동, 얻는 운영상의 이점을 세 단계로 제시한다. 두 카드의 정보량과 CTA 비중을 맞춘다.
4. **상담 전 확인:** 현장/층의 규모, 도면 보유 여부, 설치·운영 역할을 상담에서 함께 확인한다는 구체적인 안내를 둔다. 호환성이나 도입 기간을 확정적으로 약속하지 않는다.
5. **문의:** 기존 양식·API 계약·동의 및 90일 보관 안내를 유지한다. 중간과 하단에서 문의 위치로 이동할 수 있다.

## 시각 및 동작

- Figma 한국어 홈페이지의 큰 제목, 분명한 CTA, 제품 화면과 설명이 번갈아 나타나는 편집적 리듬을 참고한다. 로고·문구·그래픽은 복제하지 않는다. 기존 킨다 Navy/Blue/Paper/Coral 토큰을 사용하고 대시보드 중심의 차분한 방향을 유지한다.
- 첫 화면은 제목/설명/CTA/제품 화면이 순서대로 나타나는 짧은 등장 동작을 사용한다. 섹션은 뷰포트에 들어올 때 한 번 드러나며, 콘텐츠가 늦게 나타나더라도 스크롤을 가로막지 않는다.
- 대시보드 예시의 모니터링·제어·기록 선택은 사용자가 직접 조작하는 버튼이다. 선택된 탭과 예시 본문은 함께 바뀌고 짧게 전환된다. 자동 재생이나 무한 반복은 사용하지 않는다.
- `prefers-reduced-motion: reduce`에서는 등장·전환·장식 애니메이션을 제거한다. 키보드 포커스, 명확한 탭 상태, 320px 이상에서 가로 넘침 없음, 터치 목표 44px 이상을 유지한다.

## 변경 경계와 검증

- 공개 랜딩·대시보드 예시·해당 CSS·랜딩 테스트·`docs/menus/landing.md`만 변경한다. 로그인, 실제 관제 화면, 상담 API 및 DB 계약은 변경하지 않는다.
- 브라우저에서 1440/1024/390/320px, 접근성, 메뉴/CTA 이동, 예시 탭 전환, reduced motion, 공개 경로의 인증 비호출을 확인한다. 단위 테스트는 제거된 문구, 업무 흐름의 구체성, 고객군 균형과 예시 상태를 검증한다.
