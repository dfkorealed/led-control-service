# 킨다 시각 아이덴티티 설계

## 1. 결정 요약

킨다의 시각 아이덴티티는 기존 A안의 **시그널 그리드 심벌**, 명료한 **B2B 실무형 인상**, E안의 **오션 코랄 팔레트**, E1의 **절제된 코랄 사용 방식**을 결합한다.

- 브랜드 주 표기: 한글 `킨다`
- 심벌 방향: 시그널 그리드
- 기본색: Navy `#15324A`
- 상호작용색: Blue `#256FA1`
- 제한적 강조색: Coral `#FF7A5C`
- 밝은 배경색: Paper `#F4F8FA`
- 권장 시각 무게: Navy 60%, Blue 30%, Coral 10% 이하
- 최우선 고객 인상: 시공·유통 파트너가 제안서, 설치 문서와 제품 화면에 안심하고 사용할 수 있는 명료하고 신뢰도 높은 실무 브랜드

이 문서는 시각 체계의 제작·적용 기준을 확정한다. 브랜드 정의와 메시지 기준은 [킨다 브랜드 전략서](../../brand/kinda-brand-foundation.md)를 따른다.

## 2. 목표와 비목표

### 2.1 목표

- 제안서, 제품 화면, 설치 문서와 장비 라벨에서 하나의 브랜드로 인식되는 일관된 체계를 만든다.
- 시공·유통 파트너에게 기술적 신뢰와 현장 실용성을 전달한다.
- 브랜드 색상과 제품의 행동·상태 의미를 분리해 운영 화면의 가독성과 안전성을 지킨다.
- 작은 아이콘부터 인쇄물까지 재사용할 수 있는 최소 로고 자산군과 사용 기준을 제공한다.
- 국내 서비스에 맞춰 한글을 우선하면서 영문·숫자 정보를 자연스럽게 수용한다.

### 2.2 비목표

- 이번 문서 작업에서 최종 SVG, PNG, 앱 아이콘 또는 파비콘 파일을 제작하지 않는다.
- 앱 컴포넌트, CSS, 디자인 토큰과 기존 화면을 변경하지 않는다.
- 성공·경고·오류 의미 색상의 구체적인 색상값을 이 브랜드 팔레트로 대체하지 않는다.
- 모션 로고, 캐릭터, 일러스트레이션 체계, 광고 캠페인 그래픽과 해외용 영문 브랜드 체계는 만들지 않는다.
- 시그널 그리드 콘셉트 시안의 현재 좌표와 비례를 최종 제작값으로 간주하지 않는다.

## 3. 로고 시스템

### 3.1 기본 구성

로고의 기본형은 **시그널 그리드 심벌 + 한글 `킨다` 워드마크**의 가로 조합이다. 한글 워드마크가 브랜드 식별의 중심이며, 심벌 단독형은 앱 아이콘, 파비콘, 장비의 제한된 표기 면처럼 전체 이름을 배치하기 어려운 접점에만 사용한다.

시그널 그리드는 조명 설비의 연결과 제어 신호를 단순한 격자 구조로 표현한 **현재 단계의 콘셉트 조형**이다. 최종 벡터 제작 시 다음 기준으로 형태를 다듬는다.

- 축소했을 때 선과 면이 뭉치지 않도록 격자 수, 선 굵기와 내부 여백을 조정한다.
- 워드마크와 함께 배치했을 때 심벌이 이름보다 강하게 보이지 않도록 시각 크기를 맞춘다.
- 색상 없이도 외곽과 내부 신호 구조가 구분되게 만든다.
- 각진 산업 장비 표기와 화면 아이콘 양쪽에서 지나치게 차갑거나 장식적으로 보이지 않게 모서리와 간격을 통일한다.
- 흔한 전구, 전원 버튼 또는 무선 신호 아이콘과 혼동되는 직접 묘사를 추가하지 않는다.

### 3.2 로고 변형

최종 로고 자산은 다음 변형을 한 세트로 관리한다.

1. 기본 가로형: 밝은 배경용 심벌과 한글 워드마크
2. 반전 가로형: Navy 배경을 포함한 짙은 배경용
3. 단색 가로형: 한 가지 잉크 또는 각인 환경용
4. 심벌 단독형: 앱 아이콘, 파비콘과 제한된 장비 면용
5. 단색 심벌형: 레이저 각인, 실크 인쇄와 저해상도 출력용

로고 주변에는 심벌 내부 기본 단위 한 칸 이상의 보호 여백을 둔다. 최종 벡터 제작에서 그 기본 단위를 명시하고 모든 변형에 같은 방식으로 적용한다. 임의의 기울임, 외곽선 추가, 그림자, 그라디언트, 비율 변경과 팔레트 외 색상 적용은 허용하지 않는다.

## 4. 색상 체계

### 4.1 정확한 팔레트와 역할

| 토큰 역할 | 색상 | 주요 사용처 | 사용 제한 |
| --- | --- | --- | --- |
| Brand Navy | `#15324A` | 한글 워드마크, 제목·본문, 짙은 배경, 주요 정보 위계 | 넓은 면에서는 Paper 또는 White와 조합한다. |
| Brand Blue | `#256FA1` | 주요 버튼, 링크, 선택·활성 표시와 제품 상호작용 | 성공·경고·오류의 의미를 대신하지 않는다. |
| Brand Coral | `#FF7A5C` | 로고 심벌의 제한적 포인트, 강조 그래픽, 선택적 장식 | 흰 배경 본문, 주요 버튼, 상태 의미색에 사용하지 않는다. |
| Brand Paper | `#F4F8FA` | 제품과 문서의 기본 밝은 배경, 중립 브랜드 면 | 정보 구분이 필요하면 선·간격·명도 차를 함께 사용한다. |

White `#FFFFFF`는 출력 용지와 일반 밝은 표면에서 보조 중립색으로 사용할 수 있지만, 브랜드 면의 기본 밝은 배경은 Paper를 우선한다.

### 4.2 사용 비율

브랜드 접점 전체의 권장 시각 무게는 **Navy 60%, Blue 30%, Coral 10% 이하**다.

- Navy는 문자와 구조를 담당해 가장 큰 시각 무게를 가진다.
- Blue는 사용자의 주요 행동과 선택 가능한 요소를 구분한다.
- Coral은 한 화면이나 한 문서에서 시선을 모아야 할 소수의 브랜드 포인트에만 쓴다.
- Paper와 White 같은 중립 배경 면은 60/30/10 계산의 대상이 아니다.
- 이 비율을 개별 화면의 픽셀 면적에 기계적으로 적용하지 않는다. 화면 성격에 따라 Coral을 전혀 사용하지 않는 것도 올바른 적용이다.

### 4.3 접근성 규칙

확인된 조합의 명암비는 다음과 같다.

| 조합 | 명암비 | 적용 판단 |
| --- | ---: | --- |
| Navy / White | `13.23:1` | 본문과 제목에 사용할 수 있다. |
| Blue / White | `5.43:1` | 일반 크기 텍스트와 주요 상호작용에 사용할 수 있다. |
| Coral / White | `2.56:1` | 텍스트, 주요 버튼과 필수 정보 전달에 사용하지 않는다. |
| Coral / Navy | `5.16:1` | 로고·강조 조합에 사용할 수 있으나 장문 본문에는 사용하지 않는다. |
| Navy / Paper | `12.38:1` | 기본 제품·문서 본문 조합으로 사용한다. |

- 일반 텍스트는 WCAG AA 기준인 `4.5:1` 이상, 큰 텍스트와 의미 있는 그래픽·UI 경계는 `3:1` 이상을 충족한다.
- 색상만으로 선택, 연결 상태, 성공, 경고 또는 오류를 전달하지 않는다. 텍스트, 아이콘, 패턴, 테두리 또는 형태 중 하나 이상을 함께 제공한다.
- 제품의 주요 행동은 Blue, 본문은 Navy를 사용한다.
- 성공·경고·오류는 브랜드 Coral과 분리된 의미 색상 토큰을 사용한다. 구현 단계에서는 실제 전경·배경 조합별 명암비를 다시 측정하며, 기준을 충족하지 않는 의미 색상은 브랜드 Coral로 대체하지 않고 별도의 의미 색상 범위에서 보정한다.
- Coral을 흰 배경에 올릴 때는 의미 없는 장식이나 충분히 큰 로고 심벌에만 사용하고, 읽거나 눌러야 하는 요소로 만들지 않는다.

## 5. 타이포그래피 방향

- 모든 고객 접점은 한글 `킨다`와 한글 정보의 가독성을 우선한다.
- 본문 서체는 화면과 인쇄에서 획이 뭉치지 않고 숫자, 단위와 영문 식별자가 명확히 구분되는 고딕 계열을 사용한다.
- 제목은 본문과 같은 서체군의 굵기 차이를 우선해 실무 문서와 제품 화면의 일관성을 유지한다.
- 장비 식별 번호, 전력 수치, 시간과 표 데이터는 숫자 폭과 `0/O`, `1/I/l` 구분이 명확한 글꼴 형태를 사용한다.
- 최종 한글 서체와 영문·숫자 보조 서체는 상업적 제품, 웹 임베딩, 앱 배포, 인쇄와 파트너 템플릿 재배포를 허용하는 라이선스를 확인한 뒤 채택한다.
- 라이선스가 확인되기 전에는 특정 서체 파일을 제품 저장소나 파트너 자료에 포함하지 않는다.

## 6. 필요한 제작 자산

최종 제작 단계에서 다음 자산을 제공한다.

| 자산 | 형식 및 용도 |
| --- | --- |
| 기본·반전 가로형 로고 | 편집 가능한 SVG와 배포용 PNG |
| 단색 가로형 로고 | SVG, 흑색·백색 PNG |
| 기본 심벌 | SVG와 고해상도 투명 PNG |
| 앱 아이콘 | 운영체제별 안전 여백을 적용한 원본과 배포 크기 PNG |
| 파비콘 | SVG 파비콘과 브라우저 호환 크기 PNG/ICO |
| 단색·반전 심벌 | 장비 인쇄, 각인과 짙은 배경용 SVG/PNG |
| 컬러 명세 | HEX, RGB와 인쇄 제작 시 확인할 변환 기준 |
| 사용 예시 | 밝은 배경, 짙은 배경, 문서 표지, 제품 상단과 장비 라벨 예시 |

PNG는 SVG 원본에서 생성하며 독립적으로 형태를 수정하지 않는다. 앱 아이콘과 파비콘은 심벌 단독형을 사용하되 각 플랫폼의 마스킹과 최소 여백을 반영한다.

## 7. 적용 접점 우선순위

1. **파트너 영업 접점:** 제품 소개서, 제안서 표지, 견적·사양서의 브랜드 영역
2. **제품 식별 접점:** 로그인, 전역 헤더, 브라우저 제목, 앱 아이콘과 파비콘
3. **현장 운영 접점:** 설치 가이드, 체크리스트, 인수인계 문서와 QR 안내
4. **장비 접점:** 게이트웨이·컨트롤러 라벨, 포장과 각인
5. **대외 접점:** 홈페이지, 고객지원 페이지와 공식 채널 이미지

한 접점에서 검증한 뒤 다음 접점으로 순차 적용한다. 현재 앱과 배포 자산의 `LED Control` 표기는 적용 단계에서 목록화해 교체하되, 계약·법적 표기와 기술 식별자까지 브랜드명으로 무조건 치환하지 않는다.

## 8. 파트너 공동 표기

- 서비스 브랜드는 모든 파트너 자료에서 `킨다`로 유지한다.
- 파트너 정보는 로고 소유 관계와 분리해 `공급·시공 및 문의: 파트너사명`으로 표시한다.
- 킨다 로고는 제품·서비스 식별 영역에, 파트너 로고와 연락처는 공급·시공 정보 영역에 배치한다.
- 두 로고를 병렬 배치해야 할 때는 킨다 로고의 보호 여백을 지키고, 파트너 로고가 킨다의 소유사처럼 보이거나 킨다가 파트너의 하위 제품처럼 보이는 결합선을 만들지 않는다.
- 운영 회사명은 계약서, 약관, 개인정보 처리방침, 저작권과 사업자 정보 등 법적·운영상 필요한 위치에 별도로 표기한다.

## 9. 검증 기준

최종 자산과 적용 시안은 다음 조건을 모두 통과해야 한다.

### 9.1 로고 식별성

- 심벌 단독형을 `16px`, `24px`, `32px` 정사각 영역에서 각각 확인한다.
- 기본 가로형과 심벌형을 단색 흑색, 단색 백색, 회색조 출력에서 확인한다.
- 밝은 배경과 Navy 배경에서 외곽, 내부 격자와 워드마크가 뭉개지지 않는다.
- 실제 게이트웨이·컨트롤러 라벨의 출력 방식과 최소 크기로 시험 출력해 육안 및 카메라 촬영 상태를 확인한다.
- 레이저 각인, 단색 실크 인쇄 또는 저해상도 라벨 프린터에서 재현할 수 없는 세부 요소를 제거한다.

### 9.2 화면과 문서

- 제품의 밝은 화면에서는 Navy/Paper 또는 Navy/White를 본문 기본 조합으로 사용한다.
- 짙은 화면을 실제로 지원하는 경우에만 dark 환경을 검증한다. 지원하지 않는 dark 테마를 브랜드 검증 목적으로 새로 만들지 않는다.
- 제품의 주요 행동은 Blue로 식별되고 Coral 장식과 혼동되지 않는다.
- 문서의 컬러 출력과 흑백 출력 모두에서 제목, 본문, 표와 강조 정보의 위계가 유지된다.
- 장비 라벨과 QR 안내에서 로고가 식별 정보, 모델명, 인증 표기와 충돌하지 않는다.

### 9.3 접근성

- 텍스트와 의미 있는 UI 조합의 실제 명암비를 측정해 일반 텍스트 `4.5:1`, 큰 텍스트·UI 그래픽 `3:1` 이상을 확인한다.
- 적록·청황 색각 이상 시뮬레이션에서 주요 행동과 성공·경고·오류를 텍스트 또는 형태로 구분할 수 있다.
- 회색조에서도 선택, 비활성, 경고와 오류 상태를 색상 외 단서로 구분할 수 있다.
- 키보드 포커스와 선택 상태가 브랜드 색상에만 의존하지 않고 명확한 외곽선이나 형태 변화로 드러난다.

## 10. 후속 구현 범위와 제외 범위

### 10.1 후속 구현 범위

승인된 최종 벡터 자산을 받은 다음 별도의 구현 작업에서 아래 범위를 순차 적용한다.

1. 로고 기본형·반전형·단색형과 심벌 자산 제작 및 자산 디렉터리 편입
2. Navy, Blue, Coral, Paper의 브랜드 토큰 추가와 기존 제품 의미 토큰 분리 확인
3. 로그인, 전역 헤더, 브라우저 메타데이터, 앱 아이콘과 파비콘의 브랜드 교체
4. 파트너용 소개서·제안서와 설치·인수인계 문서 템플릿 적용
5. 게이트웨이·컨트롤러 라벨과 QR 안내의 실제 출력 시안 제작
6. 각 접점의 접근성, 소형 식별성, 흑백 출력과 파트너 공동 표기 검증

### 10.2 이번 범위에서 제외하는 작업

- 앱 및 웹 코드 수정
- CSS 변수, 디자인 토큰과 공통 컴포넌트 수정
- SVG, PNG, ICO, 폰트 파일 생성 또는 추가
- 기존 `LED Control` 표기의 실제 교체
- 장비 라벨의 발주·인쇄와 포장 제작
- 메뉴 기능, API, DB, MQTT, BLE Mesh와 펌웨어 변경
- 해외 상표, 영문 슬로건과 다국어 시각 체계 개발

후속 구현은 이 문서를 기준으로 별도의 실행 계획과 검증 절차를 거친다. 브랜드 적용으로 메뉴나 페이지 기능이 변경될 경우에만 영향을 받는 `docs/menus/*.md`를 같은 작업에서 갱신한다.
