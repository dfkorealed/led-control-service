# LED 조명 관제 서비스 UI 디자인 기획

작성일: 2026-07-02

## 1. 목표

LED 조명 관제 서비스의 PC 웹, 모바일 앱, 태블릿 화면 디자인 방향을 정의한다. 디자인은 심플하고 깔끔하며 직관적인 관제 UI를 목표로 한다. 사용자가 요청한 기준에 따라 토스의 단순한 정보 구조와 Samsung SmartThings의 기기 중심 조작감을 섞고, 파란색을 primary color로 사용한다.

이 문서는 MVP 1의 기존 메뉴 구조인 `모니터링`, `제어`, `통계`, `설정`을 유지하면서 플랫폼별 화면 구성을 구체화한다.

## 2. 디자인 원칙

### 2.1 전체 톤

- 기본 방향은 `Clean Control Center`와 `Smart Device Dashboard`의 하이브리드다.
- PC 웹은 관제 업무에 맞춰 정보 밀도와 상태 파악 속도를 우선한다.
- 모바일 앱은 현장 관리자 또는 운영자가 빠르게 상태를 확인하고 조명을 제어하는 흐름을 우선한다.
- 태블릿은 현장 점검, 설치 위치 확인, 도면 보정, 장애 대응에 맞춰 지도와 상세 패널을 동시에 보여준다.

### 2.2 시각 언어

- 흰색과 옅은 회색 배경 위에 파란색 primary color를 사용한다.
- 카드와 패널은 얇은 border, 낮은 shadow, 8px에서 18px 사이의 border radius를 사용한다.
- PC 웹의 패널은 반경을 절제해 업무 도구처럼 보이게 하고, 모바일의 기기 카드는 조금 더 부드러운 형태를 사용한다.
- 장식적 그래픽보다 실제 운영 상태, 조명 위치, 밝기, 장애 상태, 에너지 값을 우선적으로 드러낸다.

### 2.3 색상

| Primary Soft | `#E8F1FF` | 선택 배경, 조명 카드 배경, 상태 강조 |

## 3. 메뉴 구조

기본 메뉴는 모든 플랫폼에서 동일하게 유지한다.

1. 모니터링
2. 제어
3. 통계
4. 설정

PC 웹에서는 좌측 사이드바 내비게이션을 사용한다. 모바일 앱에서는 하단 탭을 사용한다. 태블릿은 하단 탭 또는 좌측 축약 메뉴를 사용할 수 있으나, MVP 1에서는 WebView 재사용을 고려해 반응형 하단 탭과 가로 화면 전용 패널 구성을 우선한다.

## 4. PC 웹 화면 설계

### 4.1 레이아웃

PC 웹은 관제실 또는 사무실에서 장시간 사용하는 화면이다. 좌측에는 메뉴, 상단에는 현장과 층 선택, 중앙에는 2D 층별 맵, 우측에는 선택한 조명 또는 이벤트 상세 패널을 둔다.

```text
좌측 메뉴 | 상단 현장/층 선택 + KPI
        | 중앙 2D 맵 + 우측 상세 패널
```

### 4.2 모니터링

- 상단 KPI: 전체 조명, 온라인, 장애, 평균 밝기, 게이트웨이 연결 상태
- 중앙: 층별 2D 맵, 조명 위치, 밝기, 상태 색상
- 우측: 선택 조명 상세, 최근 명령, 마지막 수신 시간, RSSI/hop count
- 장애 조명은 붉은색, 오프라인은 회색, 정상은 파란색 또는 청록색 상태 표시를 사용한다.

### 4.3 제어

- 대상 선택: 개별 조명, 그룹, 구역
- 제어 방식: 전원 토글, 밝기 슬라이더, 프리셋 버튼, 적용 버튼
- 보조 탭: 수동 제어, 스케줄, 이벤트 정책
- 명령 전송 후 pending, acknowledged, failed 상태를 명확히 보여준다.

### 4.4 통계

- 일/월/년 전력 사용량과 예상 전기료를 카드로 표시한다.
- 중앙에는 사용량 추이 차트, 우측에는 층별 또는 그룹별 비교를 둔다.
- 추정치 기반임을 표시하되, MVP 2 이후 실측/보정 데이터로 확장 가능한 구조를 유지한다.

### 4.5 설정

- 좌측 또는 상단의 내부 설정 탭: 현장, 건물/층, 도면, 조명 배치, 그룹, 게이트웨이, OTA, 사용자 권한
- 도면과 조명 배치 설정은 PC 웹에서 가장 상세하게 제공한다.
- OTA는 MVP 1에서는 메뉴 구조와 상태 카드만 제공하고, 실제 배포 제어는 MVP 2에서 확장한다.

## 5. 모바일 앱 화면 설계

### 5.1 레이아웃

모바일은 WebView shell을 기준으로 하며, 하단 탭과 카드 리스트 중심으로 설계한다. 지도는 그대로 축소하지 않고 간소화 맵 또는 리스트 전환으로 제공한다.

```text
상단 현장 선택
상태 요약 카드
장애/조명/그룹 리스트
하단 탭
```

### 5.2 모니터링

- 첫 화면은 현재 현장의 상태 요약 카드로 시작한다.
- 온라인/장애/평균 밝기/게이트웨이 상태를 한눈에 보여준다.
- 장애 또는 오프라인 조명 리스트를 우선 노출한다.
- 지도는 별도 보기로 제공하고, 기본은 리스트 탐색을 우선한다.

### 5.3 제어

- 조명 카드 안에서 전원 토글과 밝기 상태를 보여준다.
- 상세 화면에서 큰 밝기 슬라이더, 전원 토글, 프리셋을 제공한다.
- 위험한 일괄 제어는 확인 단계를 둔다.

### 5.4 통계

- 월 사용량, 예상 전기료, 전월 대비 증감, 절감 추정치를 요약한다.
- 상세 차트는 PC 웹보다 단순하게 제공한다.

### 5.5 설정

- 계정, 알림, 현장 전환, 앱 설정을 우선한다.
- 도면 편집, OTA 배포, 권한 관리처럼 복잡한 설정은 PC 웹 또는 태블릿으로 유도한다.

## 6. 태블릿 화면 설계

### 6.1 레이아웃

태블릿은 현장 점검자와 설치 담당자가 들고 다니며 쓰는 화면을 기준으로 한다. 가로 화면에서 지도와 상세 패널을 동시에 보여주는 구조를 우선한다.

```text
상단 현장/층/모드 선택
좌측 또는 중앙 2D 맵
우측 선택 조명/점검/제어 패널
```

### 6.2 모니터링

- 2D 맵을 크게 표시하고, 조명 카드 또는 점 형태로 상태를 보여준다.
- 선택한 조명의 상세 정보와 점검 체크 항목을 우측에 표시한다.
- 통신 품질 heatmap은 MVP 2 이후 확장한다.

### 6.3 제어

- 지도에서 조명을 선택하면 우측 패널에서 즉시 밝기와 전원을 조정한다.
- 그룹 제어는 현장 실수 방지를 위해 대상 범위와 예상 영향을 먼저 보여준다.

### 6.4 설정

- 도면 보정, 조명 위치 이동, 그룹 지정 같은 현장형 설정에 강점을 둔다.
- 손가락 터치를 고려해 조명 핸들, 선택 영역, 저장 버튼의 크기를 충분히 확보한다.

## 7. 컴포넌트 규칙

### 7.1 내비게이션

- PC: 좌측 사이드바, 아이콘과 텍스트를 함께 표시
- 모바일: 하단 탭, 아이콘 중심에 짧은 라벨
- 태블릿: 화면 폭에 따라 하단 탭 또는 축약 사이드 내비게이션

### 7.2 상태 카드

- 카드에는 라벨, 주요 수치, 보조 설명, 상태 색상을 포함한다.
- PC의 KPI 카드는 촘촘하게, 모바일의 상태 카드는 크게 표시한다.

### 7.3 조명 표시

- 맵 위 조명은 상태와 밝기를 함께 드러낸다.
- 정상: 파란색 또는 청록색 강조
- 장애: 붉은색 강조
- 오프라인: 회색 비활성
- 선택됨: primary blue 테두리와 soft blue 배경

### 7.4 제어 입력

- 전원은 토글, 밝기는 슬라이더, 모드는 segmented control, 스케줄은 리스트와 시간 입력을 사용한다.
- 주요 실행 버튼은 primary blue로 통일한다.
- 대량 제어, OTA, 설정 저장처럼 영향이 큰 동작은 확인 상태를 둔다.

## 8. MVP 우선순위

### 8.1 MVP 1 디자인 적용 범위

1. PC 웹 레이아웃 개선: 좌측 메뉴, KPI, 2D 맵, 상세 패널
2. 모바일 반응형 개선: 하단 탭, 상태 요약 카드, 리스트 중심 모니터링
3. 태블릿 가로 레이아웃: 지도와 상세 패널 동시 표시
4. 공통 디자인 토큰: primary color, 상태 색상, card, panel, button, tab, slider
5. 설정 메뉴 구조 정리: 현장, 층/도면, 그룹, 게이트웨이, OTA

### 8.2 MVP 2 이후 확장

- 통신 품질 heatmap
- 실제 RSSI, hop count, 명령 성공률, 응답 지연 표시
- OTA 배포와 롤백 화면
- 도면 편집과 조명 위치 수정 UX 고도화
- 파일럿 현장 운영 리포트

## 9. 검증 기준

- PC 웹에서 관제자가 5초 안에 전체 조명 수, 장애 수, 평균 밝기, 게이트웨이 상태를 파악할 수 있어야 한다.
- 모바일에서 장애 조명과 빠른 제어 화면까지 두 번 이하의 탭으로 접근할 수 있어야 한다.
- 태블릿 가로 화면에서 지도와 선택 조명 상세가 동시에 보여야 한다.
- primary blue가 명령, 선택, 주요 정보의 기준색으로 일관되게 사용되어야 한다.
- 장애, 오프라인, 정상 상태가 색상과 텍스트 모두로 구분되어야 한다.
- 320px 모바일 화면에서도 주요 텍스트와 버튼이 겹치거나 잘리지 않아야 한다.

## 10. 승인된 방향

사용자는 `Clean Control Center`와 `Smart Device Dashboard`를 적절히 섞은 방향을 승인했다. 따라서 이후 구현 계획은 A+B 하이브리드 방향을 기준으로 작성한다.
