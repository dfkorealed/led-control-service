# 공통 맵 요소·편집기 통합 및 고성능 렌더링 설계

갱신일: 2026-09-19

상태: **통합 방향 대화 승인, 작성본 검토 대기. 아래 목표 구조는 미구현이다.** 기존 문서를 갱신하며 이전 분리형 구현 증거는 실행 계획 Task 1~14와 Git 이력에 보존한다. 이번 문서 작성에서는 코드·DB·사용자 맵을 변경하지 않는다. 작성본 승인 후 상세 구현 계획을 작성한다.

## 1. 목적과 범위

CAD에서 가져온 도형과 직접 만든 도형을 구분하지 않고 같은 방법으로 선택·수정·삭제할 수 있게 한다. 네모·세모·선·텍스트 외에 필요한 도형을 일반 도구에 추가한다. 조명 1,000개와 대량 도형이 있는 층도 확대·이동·편집하기 편하도록 렌더링과 화면 구성을 개선한다.

- DWG/DXF는 공통 요소를 생성하는 입력 형식이다. CAD 전용 요소 유형·속성 패널·삭제 경로를 새로 만들지 않는다.
- 층별 맵, 실제 조명 배치, 후보 슬롯, 기존 권한·편집 잠금·충돌 보호를 유지한다.
- 편집기를 화면 안에 고정하고 도구·속성 패널만 필요한 만큼 스크롤한다.
- 성능 수치는 목표이며 아직 달성한 결과가 아니다. AutoCAD와 같은 성능이라고 주장하지 않는다.
- PDF·PNG·JPG 신규 가져오기, AI 호출, 장비 테스트는 이번 범위가 아니다.

## 2. 현재 구조와 선택한 방향

현재 수동 도형은 `FloorMapObject`, 가져온 도형은 `FloorCadScene`과 타일 및 override에 나뉜다. 수동 도구는 네모·세모·선·텍스트이며 CAD 속성에는 별도의 숨김 기능이 있다. CAD 수정은 수동 도형의 실행 취소·저장·리비전 이력과 같은 경로를 사용하지 않는다. override 삭제 또한 원본 요소 삭제가 아니라 수정 초기화다.

선택한 방향은 **공통 편집 데이터와 명령을 정본으로 삼고 GPU 배치를 표시 캐시로 유지하는 방식**이다. 기존 PixiJS 배치와 제한된 Konva 편집 오버레이를 재사용한다. 표시 이름만 바꾸거나 모든 도형을 개별 Konva 노드로 만드는 대안은 채택하지 않는다.

조사에서 확인한 최적화 후보는 저장 후 렌더러 재생성, 확대 단계 변경 시 원본 타일 재요청, 이동 중 비동기 원본 준비 대기, 타일 요청별 전체 원장 반복 검사다. 실제 지연 비중은 구현 전 계측으로 확인한다.

## 3. 공통 요소 모델

논리 모델은 `MapElement`로 통일한다. 아래는 목표 계약이며 기존 DB에 이미 존재하는 모델을 뜻하지 않는다.

| 항목 | 규칙 |
| --- | --- |
| 식별자 | 층 내 안정적인 ID. 저장·이동·실행 취소로 바뀌지 않는다. |
| 도형 | rectangle, triangle, line, text, ellipse, arc, polyline, polygon |
| 좌표 | 도형별 원본 geometry와 명시적인 변환, 정규화된 맵 좌표 |
| 스타일 | 선·채우기·선 두께·문자 크기 등 해당 종류에 유효한 속성 |
| 구성 | 일반 그룹·레이어·겹침 순서·표시·잠금 |
| 출처 | 선택적인 가져오기 작업·원본 식별 정보. 편집 방식이나 권한을 나누지 않는다. |

- 원은 가로·세로가 같은 타원이다. 연속선과 다각형은 열린 선과 닫힌 면을 구분한다.
- 모든 유형은 일반 도구에서 직접 만들 수 있다. 출처와 무관하게 같은 속성 패널을 사용한다.
- 크기·위치·회전·스타일, 선 끝점, 호 시작/끝 각도, 문자열을 수정할 수 있다. 연속선·다각형은 생성과 전체 변환을 지원하며 CAD급 개별 꼭짓점 편집은 제외한다.
- 잠긴 요소는 잠금 해제 후 수정·삭제한다. 다중 명령에 잠긴 요소가 포함되면 전체 명령을 거부하고 이유를 알린다.
- 원본 geometry는 화면용 단순화·타일 분할 이전에 확보한다. GPU 배치에서 편집 원본을 역추출하지 않는다.

## 4. CAD 변환과 적용

기존 영역 탐지·선택과 변환 보안 경계를 재사용한다. 선택 영역을 공통 요소로 변환한 뒤 표시용 타일·LOD와 조명 후보를 만든다.

| CAD 입력 | 공통 요소 결과 |
| --- | --- |
| LINE, TEXT, MTEXT | 선·일반 텍스트. 미지원 문자 서식은 변환 결과에 표시 |
| LWPOLYLINE, POLYLINE | 연속선·다각형. 정확히 판정되는 네모·세모는 해당 도형 |
| CIRCLE, ELLIPSE, ARC | 타원·호. 현재 미흡한 ELLIPSE 입력도 지원 대상으로 포함 |
| INSERT | 일반 요소의 그룹. 반복 배치 경로를 포함해 ID 충돌 방지 |
| DIMENSION | 선·텍스트 등으로 구성한 일반 그룹 |
| HATCH | 일반 다각형·복수 경로 그룹. 내부 구멍을 보존 |

구멍 있는 면은 내부 링을 지원하는 일반 다각형 geometry와 속성으로 표현한다. 일반 도구에서도 내부 링 추가·제거를 지원하며 CAD 전용 채움 객체를 만들지 않는다. 지원 불가능한 외부 참조·3D·문자 표현은 누락 개수와 이유를 표시하고, 지원한 것처럼 처리하지 않는다.

검토 화면에는 선택 영역 확대·이동, 후보 선택, 변환 개수와 제외 사유를 제공한다. 적용 전에 기존 도형 교체와 실제 조명의 미배치 전환을 확인받는다. 준비된 새 맵과 후보 슬롯을 원자적으로 활성화하며 실패하면 기존 맵을 유지한다. 슬롯은 위치 후보이며 실제 하드웨어 자동 등록이 아니다.

## 5. 공통 편집·삭제·저장

- 모든 도형은 공통 add/update/delete 명령, 선택 모델, 속성 패널, 실행 취소/다시 실행을 사용한다.
- 삭제는 현재 맵 요소 집합에서 제거하는 동작이다. 숨김으로 대신하지 않는다. 저장·재조회·모니터링에서도 없어야 한다.
- 그룹 단일 클릭은 그룹 전체, 내부 요소 더블클릭은 해당 요소를 선택한다. 다중 수정·삭제는 하나의 명령과 실행 취소 단위다.
- 실행 취소는 ID·geometry·스타일·그룹 관계를 복원한다. 저장 전에는 로컬 초안을 되돌리고, 저장 후에는 역변경을 새 미저장 초안으로 만든다.
- CAD의 즉시 별도 저장을 없애고 공통 저장 버튼으로 확정한다. 이탈·층 전환에 미저장 보호를 적용한다.
- 저장은 층 권한, 편집 lease, 기준 mapRevision을 검사해 한 번에 적용한다. 충돌 시 초안을 보존하고 재조회·재시도 경로를 제공한다.
- 실제 조명 제거는 기존대로 확인 후 **미배치**로 바꾼다. 일반 도형 삭제가 장비·측정 이력·등록 정보를 삭제하지 않는다.
- 조명 심볼과 후보 슬롯은 별도 객체다. 심볼 삭제는 슬롯·실제 조명 삭제를 전파하지 않는다. 원본 요소 참조는 선택적 출처 정보이며 삭제 후에도 슬롯 위치를 유지한다. 슬롯 제거·실제 조명 미배치는 각각 명시적인 동작이다.

## 6. 저장·이력 경계

공통 요소의 불변 기본 청크와 제한된 변경분을 정본으로 사용한다. 수동 도형과 가져온 도형에 동일한 명령과 읽기 계약을 적용한다. 요소 ID 조회 인덱스는 편집 원본을 찾고, 타일 인덱스는 화면 범위를 찾는다.

- 도형 수만큼 DB 행·DOM·Konva/Pixi 객체를 생성하거나 저장마다 전체 도형을 JSON 복제하지 않는다.
- 표시 타일은 재생성 가능한 파생 자산이다. 삭제·geometry 변경은 정본 변경분에 기록한다.
- 문서 generation, 내용 리비전, 파일 형식 버전을 구분한다. 재적용으로 형식 버전을 증가시키지 않는다.
- 이력은 기본 generation과 변경분 위치를 참조한다. 체크포인트로 조회 비용을 제한하고 보존 중인 이력의 참조 자산은 정리하지 않는다.
- 일반 저장은 제한된 변경 수·본문 크기로 처리한다. 대량 가져오기·대량 삭제는 서버 준비 작업으로 검증한 뒤 하나의 리비전으로 확정한다. 부분 성공을 전체 성공으로 표시하지 않는다.
- 실제 테이블·DTO·수치 한도는 승인 후 공유 계약 작업에서 기존 제한과 함께 확정한다. 현재 수동 저장의 2,000 변경/1 MiB 제한은 전체 보관 요소 수 한도가 아니다.
- 기존 CAD 테이블은 전환 호환용이며 새 기능의 분리 정본으로 계속 확장하지 않는다. 스키마 변경 시 database-schema.md를 같은 작업에서 갱신한다.

## 7. 기존 맵 보존과 전환

수동 도형, 가져온 도형, overrides, 레이어, 실제 조명 배치, 슬롯과 보존 리비전을 확인한 뒤 별도 generation으로 전환한다. 사용자 DB 적용은 백업·대상 확인·승인을 거친다.

기존 타일에는 **동일 ID의 geometry가 여러 조각으로 분할되어 있을 수 있다.** ID별 마지막 값만 남기거나 조각을 무조건 이어 붙이는 변환은 금지한다.

1. 보존 원본과 해당 변환 프로필로 완전한 geometry를 복구하고 ID·좌표를 대조한다.
2. 원본 복구가 불가능하면 검증된 모든 조각을 안정적인 하위 ID의 일반 요소 그룹으로 보존한다. 복원할 수 없는 연결 순서를 만들지 않는다.
3. 이동·스타일·숨김 override와 레이어 상태를 반영한다. 과거 숨김은 삭제로 추정하지 않는다.
4. ID 참조, 요소/조각 개수, bounds, 스타일, 슬롯·조명 위치와 화면을 비교한다. 검증 불가능하면 활성화하지 않는다.
5. 검증된 generation만 원자적으로 활성화한다. 실패하면 이전 맵·이력을 유지한다.

전환 중 해당 층의 쓰기를 잠그되 기존 읽기는 유지한다. 기존 리비전은 호환 읽기/복구 어댑터로 새 문서 초안에 복원한 뒤 검증·활성화한다. 복구 불가능한 자산은 명확히 알리고 현재 맵을 보존한다. 확인되지 않은 과거 데이터를 제거하지 않는다.

## 8. 렌더링과 서버 최적화

PixiJS WebGL을 공통 도형 배치 렌더러로 재사용한다. Konva는 조명·선택 핸들·보조선과 선택 중인 요소에 한정한다. 전체 도형을 중복 렌더링하지 않는다.

- 이동은 카메라를 즉시 변환한다. 원본 조회 완료를 기다리지 않는다.
- 확대 단계가 바뀌어도 검증된 원본 바이트를 재사용하고 Worker에서 표시 geometry를 만든다.
- 변경 요소의 이전/새 영역만 갱신한다. 저장 리비전 변경만으로 렌더러를 파괴하지 않는다.
- 화면과 주변 타일을 우선 표시하고 저배율은 구조를 식별할 수 있는 벡터 LOD를 사용한다. 중앙만 남기거나 정본을 삭제하지 않는다.
- 메모리 예산·LRU·GPU 해제·취소·오래된 응답 무시를 유지한다. 캐시 퇴출·generation 변경 뒤 재요청은 정상이다.
- 포인터·카메라의 프레임 상태를 React 패널 상태와 분리한다. 정지 화면은 변경 시에만 그린다.
- 공간 인덱스와 화면 8px 오차·겹침 순서로 선택한다. 다중 선택도 전체 순회를 피한다.
- 서버는 검증된 불변 manifest/원장의 제한된 캐시와 동시 요청 병합을 사용한다. 키에 자산 ID·해시·크기·generation을 포함한다.
- 권한·현재 generation·작업 상태는 매 요청 확인하며 권한 결과를 공유 캐시하지 않는다. 자산 불변성이 증명되지 않으면 HEAD 검사를 단순 TTL로 생략하지 않는다.
- 비공개 자산·SHA-256·크기·본문 한도·정리 상태 검사를 유지한다. UI에는 검증된 DTO를 반환하고 원시 파일에 없는 필드를 가정하지 않는다.

## 9. 맵 크기와 화면

논리 크기와 실제 canvas를 분리한다. 기본 긴 변 16,384, 최대 32,768을 유지한다. 짧은 변은 기본 최소 1,024이며 극단적 종횡비는 긴 변 상한을 우선하고 최소 512까지 허용한다. 여백은 긴 변 2%·최소 64, 짧은 변 1/4을 상한으로 한다. 기본 격자는 긴 변 약 1/200에 가까운 5 단위 값, 10~100 범위다. 타일 기준 크기는 512다.

맵 교체·첫 진입·층 전환은 전체 맞춤을 사용한다. framebuffer는 화면 크기만 할당한다. 선택 영역 500,000개·전체 확장 1,000,000개 한도를 유지하고 초과는 명시적으로 거부한다.

- 상단: 층, 실행 취소/다시 실행, 확대·맞춤, 저장. 공통 아이콘 버튼·툴팁 사용.
- 좌측: 일반 도형 도구, 미배치 조명 목록·검색. 패널 내부 스크롤.
- 중앙: 남은 공간을 채우는 canvas. 외부 배경 단색, 맵 내부 격자 유지.
- 우측: 단일/다중 선택에 맞는 공통 속성. 미선택이면 맵 크기만 표시.
- 좁은 화면: 패널 접기/시트. 세 패널을 세로로 길게 쌓지 않는다.

편집 경로에만 100dvh 기준 가용 높이와 min-height: 0 체인을 적용한다. 다른 설정 페이지의 스크롤을 막지 않는다. 휠은 확대·축소, 맵 잡기 드래그는 이동, 이동 중 커서는 움켜쥔 손이다. deltaMode로 장치 종류를 추정하지 않는다. 스냅은 이동 종료 시 적용하고 보조선을 보존한다.

모바일 WebView도 같은 데이터·렌더러를 사용하며 고빈도 입력을 RN bridge로 보내지 않는다. context loss·백그라운드 복귀에는 현재 화면부터 복원한다. WebGL 실패는 명시적 오류·재시도 상태이며 이미지 배경으로 조용히 대체하지 않는다. 기존 SVG-only 맵의 읽기 호환은 별개로 유지한다.

## 10. 검증 및 완료 기준

아래는 후속 구현의 검증 기준이며 이번 문서 변경의 테스트 결과가 아니다.

| 구분 | 합격 조건 |
| --- | --- |
| 요소 | 직접 생성/가져오기 모두 유형별 수정·이동·크기·회전·삭제·실행 취소 |
| 저장 | 저장→새로고침→모니터링 동일 결과. 삭제 도형 재등장 없음. 장비 정보 보존 |
| 전환 | 타일 경계 긴 선·반복 블록·override·레이어·슬롯·이력 비교 |
| 실패 | 권한·lease·충돌·자산 손상·전환 실패 시 현재 맵 보존 |
| UI | 1440/1024/390/320px에서 body overflow·도구 겹침 없이 사용 |
| 실제 브라우저 | 제공된 두 DWG 가져오기→검토→적용→수정/삭제→저장→새로고침→모니터링 |

같은 기기·브라우저·도면·viewport에서 변경 전후를 비교하고 cold/warm을 구분한다. 실제 두 DWG, 1,000개 조명, 최대 300,000개 도형의 별도 합성 자료를 구분해 기록한다.

- warm 진입 p95 3초 이내 목표
- 이동·확대 프레임 p95 16.7ms 목표, desktop 33ms 상한
- 클릭 선택 p95 120ms 이내 목표
- 캐시 내 동일 영역 왕복·확대 시 원본 중복 다운로드 없음
- 이동 중 전체 재파싱, 단일 도형 저장 후 전체 렌더러 재생성 없음
- 요청 수·전송량·long task·CPU/GPU 캐시 사용량과 표시 완결성을 함께 보고
- 모바일 WebView p95 33ms 목표는 실제 iOS/Android에서 별도 확인. desktop 모바일 viewport로 달성 선언 금지

삭제·복구 여정은 격리 시험용 층/DB에서 수행한다. 현재 사용자 맵을 변경하는 테스트는 별도 확인 후 진행한다. BLE/LED 하드웨어 검증으로 해석하지 않는다.

## 11. 구현 경계와 후속 승인

공유 모델·명령과 보존 방식이 프론트/백엔드의 선행 계약이다. 이후 서버 저장·변환, 공통 편집·렌더러를 연결하고 UI·브라우저 검증을 통합한다. 기능 공통화 없이 표시 이름만 바꾸면 완료가 아니다.

작성본 승인 후 기존 실행 계획에 작은 작업 단위·소유 파일·실패 테스트·검증 명령·커밋 경계를 작성한다. 기존 Task 1~14를 새 구조 구현 완료로 재해석하지 않는다. 상세 계획 승인 전 제품 코드·의존성·DB 변경은 진행하지 않는다.

제외 범위는 CAD급 꼭짓점/제약 편집, 3D·외부 래스터·전체 폰트 완전 호환, 여러 영역 합성, WebGPU 운영 활성화다. AI 연결점은 보존하지만 호출하거나 비용을 발생시키지 않는다.
