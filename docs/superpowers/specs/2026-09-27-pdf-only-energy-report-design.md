# PDF 전용 에너지 보고서 설계

기준일: 2026-09-28

## 목적과 승인된 시안

Excel 생성·표시·다운로드 기능과 기존 보고서 생성 이력을 제거한다. CSV 원본 내보내기는 보고서와 별개의 기능으로 유지한다. 최초 6쪽 A4 시안 `energy-report-pdf-only-2month-demo.pdf`의 해석 범위·읽는 방법·순위 하단 설명 카드를 제거하고 히트맵 셀을 정사각형으로 만든 요구를 유지한다. 2026-09-28 사용자 승인 주석에 따라 표지를 독립시켜 완전한 2개월 현장 데이터는 7쪽 `energy-report-annotated-2month-demo.pdf`로 출력한다. 기존 시안은 보존하며 제목·값·단위·비교 불가 사유 등 판독에 필요한 정보를 남긴다.

## 문서 구성

1. 중앙 제목 `조명 에너지 사용 보고서`와 현장·보고 범위·기간만 있는 표지. 글꼴 폭으로 각 줄을 중앙 정렬하고 긴 이름을 줄바꿈한다. 브랜드와 쪽 번호는 표지에서 생략한다.
2. `핵심 결과`: 이번/직전 동일 일수 사용량과 기록상의 차이, 저장 비용, 비교 막대 또는 비교 불가 사유.
3. 일별 사용량 추이, 월별 합계, 최고 기록일.
4. `사용량 순위`: 층별 사용량, 상위 5개 조명과 그 외 조명. 귀속 불가능한 사용량은 별도 항목으로 남긴다. 층·조명 분할의 계속 페이지는 `사용량 순위 (계속)` 제목을 쓴다.
5. `시간대별 사용량`: 요일×시간 에너지 히트맵(24×7 정사각형 셀), 최대 셀과 주요 시간대, 비교·비용 산식 및 자료 부족 사유.
6쪽 이후. 날짜·사용량·저장 비용의 3열 월별 일별 상세. 2개월·62일의 완전한 사례에서는 6~7쪽에 각각 31행을 싣는다. 기간 길이와 자료 상태에 따라 페이지 수는 동적으로 변한다. 본문 쪽 번호는 실제 문서 번호를 유지해 완전 사례에서 `2 / 7`부터 표시한다.

자료 상태 단어를 바꾸는 대신 요약의 자료 확인 카드, 히트맵 자료 상태 라벨·값, 일별 상세 자료 열을 제거한다. UTC/현장 시간대와 생성 시각도 PDF 본문에서는 제외하되 불변 원본 문서의 메타데이터는 유지한다. 내부 완전성 판정·비교 차단과 0/결측 구분은 그대로 둔다. 상태 열 없이 부분 값이 완전한 하루 합계로 보이지 않도록 부분·확인불가 일별 전력량과 비용의 공개 text는 `집계 불가`, 결측 날짜는 `데이터 없음`으로 표시하며 내부 raw·known/expected 값은 보존한다. 완전 날짜의 비용만 결측인 경우에도 기존 `데이터 없음`을 유지한다. 요약·귀속·비교 계산과 부분 귀속 값의 표시는 바꾸지 않는다.

모든 수치는 한 불변 스냅샷에서 계산하며, 반올림 전 원시 합계와 월·일·층·조명·히트맵의 관계를 검증한다. 전력량 표시 자릿수는 선택된 원본 값의 소수 정밀도에 맞춰 2~4자리로 한 문서 안에서 통일하고, 표시 반올림 때문에 합계가 달라 보이지 않게 한다. UUID, raw/display 중복, `null`, 24시간 가상 기준선, 정격 W 기반 추정 절감량, 밝기 히트맵, 중복 소속될 수 있는 그룹 순위는 표준 PDF 본문에서 제외한다. 제품의 저장 집계는 계량기 실측의 증거가 아니므로 `실측`, `실제 계량`, 검증된 `절감`이라고 부르지 않는다. 비교는 현재·직전 동일 일수의 충분한 기록이 확인될 때만 표시한다. 결측을 0으로 대체하거나 차트 선으로 연결하지 않는다. 저장 비용은 당시 저장된 비용만 사용하며 청구액이나 검증된 요금 절감액이라고 부르지 않는다. 자료가 부족하면 해당 수치를 `비교 불가` 또는 `데이터 없음`으로 표시하고 이유를 명시한다.

## UI·API·데이터 전환

- 생성 UI와 새 작업 계약은 PDF만 허용한다. 이력의 형식 필터·열·카드 라벨과 랜딩의 Excel 홍보를 제거한다. 기존 URL의 `format` 파라미터는 오류 없이 버리고 1쪽으로 정규화한다.
- CSV는 형식 필드와 무관한 범위 검증으로 분리한다.
- 기존 `EnergyReportJob` 전체는 배포 시 일회성 순방향 migration에서 삭제한다. 삭제 트리거가 만든 `EnergyReportObjectCleanup` 원장은 보존하고, 모든 S3 객체의 HEAD/DELETE가 완료될 때까지 Excel 키 검증 경로를 유지한다. 구 API/worker의 신규 생성과 PUT을 중지한 상태에서 migration을 적용한다. 구 migration은 수정하지 않는다.
- 스키마의 보고서 형식 enum은 PDF만 남긴다. 객체 원장에는 과거 Excel 파일 키가 남을 수 있으므로 원장 정리가 끝나기 전 저장소의 legacy 키 삭제 경로는 제거하지 않는다. 실제 환경의 데이터 삭제 및 객체 삭제는 환경 식별·백업·유지보수 경계 확인 후에만 실행한다.
- PDF 렌더러는 기존 pdf-lib·NotoSansKR 자산과 불변 문서를 사용한다. 레이아웃과 표시 모델은 기계 검증용 manifest와 분리한다. 텍스트는 폰트 폭을 측정해 감싸고, 표 행과 그래프의 페이지 경계·충돌을 검증한다.

## 검증 기준

- 새 API는 PDF 요청을 수용하고 XLSX 요청을 거부하며, 새 파일은 PDF MIME·확장자만 사용한다.
- 62일 시안형 fixture에서 표지 뒤 2~5쪽의 수치와 6~7쪽의 62개 일별 행이 일치하고 PDF 텍스트가 겹치거나 잘리지 않는다. 긴 현장·대상 이름의 줄별 중앙 정렬, 17개·20개 층 분할, 큰 비용, 부분·확인불가 추이 단절과 고립된 완전 기록일의 점을 회귀로 검증한다.
- 부분 기록·0과 결측·대상 귀속 공백·긴 한글 이름·기간 길이·DST 경계가 사실과 다르게 표시되지 않는다.
- 이력 초기화 migration 뒤 보고서 행은 0이며 cleanup 원장은 삭제되지 않는다. 늦은 PUT 가능성이 해소된 상태에서 저장소가 비워지는지를 검증한다.
- 변경된 통계/랜딩 메뉴 문서, 프로젝트 상태, DB 구조 문서를 코드 상태와 맞춘다.

## 로컬 예시 생성과 검수

`apps/api/scripts/generate-energy-report-sample.ts`는 `makePdfRichFixture`의 62일·2개 층·6개 조명 가상 데이터를 실제 pdf-lib 제품 렌더러로 출력한다. `pnpm --filter @led-control/api exec tsx scripts/generate-energy-report-sample.ts '/절대/출력/경로.pdf'`로 실행하며 명시적인 출력 인수가 필요하다. DB·S3 연결이나 서버 변경 없이 파일을 생성하며, 기존 파일은 exclusive 생성으로 덮어쓰기를 거절한다. 사용자 작업 폴더의 `output/pdf/energy-report-annotated-2month-demo.pdf`를 7쪽 전체 PNG로 렌더해 중앙 정렬·표·그래프·쪽 번호와 겹침·잘림 부재를 검수한다. 예시의 수치는 실제 현장·하드웨어 검증 결과가 아니다.
