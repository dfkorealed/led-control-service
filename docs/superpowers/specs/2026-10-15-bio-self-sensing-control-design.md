# BIO 조명의 자기 감지 밝기와 유지시간 설정 설계

기준일: 2026-10-15

방습등1·방습등2를 포함한 센서 조명은 자신이 움직임을 감지하면 자신의 밝기를 변경하고, 마지막 감지 이후 설정한 시간이 지나면 기본 밝기로 복귀한다. 유지시간은 **1~1,800초의 정수**로 설정한다. 기존 조명과 새로 등록하는 조명은 같은 화면과 공통 처리 경로를 사용한다.

상태: 사용자가 설계·구현 진행을 승인했다. 별도 브랜치에서 최소1초 코드와 저수준 설정 조회/적용/복구를 구현·검증 중이다. 전체 규칙/서버/UI 연결·메인 병합·실제1초 설정/복귀는 아직이며, 실제 장비 작업 전 별도 승인 관문을 유지한다.

## 설정 화면과 기존 동작

- 기존 이벤트 추가/수정 화면에 `감지한 조명도 제어` 선택을 제공한다. 자기 조명만 제어하면 실행 조명을 다시 고르지 않는다. 다른 조명 연동도 유지한다.
- 새 규칙은 자기 조명 제어를 기본 선택한다. 기존 규칙은 기존 실행 대상과 동작을 보존하고, 사용자가 자기 제어를 선택하기 전 자동 전환하지 않는다.
- 기존 밝기·유지시간 입력을 재사용한다. 최소 1초·1초 단위이며 기본 60초·최대 1,800초를 유지한다. 저장된 10초·60초 등의 값은 일괄 변경하지 않는다.
- 한 규칙의 감지 조명은 현재 BIO와 같이 한 대다. 방습등1과 방습등2는 각각 규칙을 설정하여 서로의 감지로 불필요하게 함께 켜지지 않게 한다. 다중 규칙 일괄 생성 화면은 추가하지 않는다.
- 조명 이름이나 과거 A/B ID로 분기하지 않는다. 기존/신규 모두 현재 등록 정보와 장비 식별에 맞는 공통 호환 처리를 자동 적용한다. 사용자에게 별도의 프로파일 등록·개발자 확인 절차를 요구하지 않는다.

## 센서 모드를 유지하는 자기 제어

현재 UI·API·Gateway는 활성 BIO 감지 조명을 일반 실행 대상에서 제외한다. `BioDongleClient.setOutput`은 양수 밝기에서 `force-on`, 0%에서 `force-off`로 모드를 바꾸므로, 제한만 제거하면 센서 모드를 보존하지 못한다.

자기 조명은 센서 모드를 유지하는 장비 자체 설정 경로로 제어한다. 감지 시 밝기·무감지 시 기본 밝기·유지시간을 설정하고 조명 자체 센서가 출력 전환과 재감지 연장을 수행한다. Gateway 타이머로 자기 조명의 force-on/off를 반복하는 방식은 사용하지 않는다. 다른 조명은 기존 서비스 감지·유지·복귀 경로를 유지한다.

출발 시점의 codec은 감지 밝기와 모드 설정/조회만 제공했다. 이후 정적 앱 분석 및 승인된3대의 실제 설정 조회를 근거로 유지시간·무감지 밝기의 저수준 설정 코드를 구현했다. 실제 쓰기/출력 전환은 별도 확인하며, 확인되지 않은 opcode를 추측해 전송하지 않는다.

## 최소 1초와 장비 호환

서비스 입력·서버 검증·저장·snapshot·Gateway의 BIO 유지시간 처리를 1초 단위로 맞춘다. 화면만 1초로 낮추거나 서버에서 10초로 보정하지 않는다. 기존 BlueZ 경로는 이번 기능에 확장하지 않으며 BIO 전용 제약과 분리한다.

공통 호환 프로파일은 근거로 확인된 자기 제어 지원, 유지시간 최소/최대/단위와 밝기 표현 범위를 구분한다. 장비가 1초를 정확히 표현하고 독립 조회로 확인해야 1초 설정을 적용 완료로 표시한다. 해당 값을 표현하지 못하면 적용을 거절하고 이유를 안내한다. 단위를 몰래 반올림하거나 검증되지 않은 장비군까지 지원 완료로 처리하지 않는다. 장비 자체가 1초를 지원하지 않으면 펌웨어 지원이 필요한 결과를 보고하고 해당 장비의 기능 활성화를 중단한다.

자기 제어의 0%를 일반 `force-off`로 대체하지 않는다. 센서 모드를 유지하는 출력 0% 표현이 확인되면 사용하고, 확인 전에는 해당 값 적용을 차단하고 이유를 안내한다. 다른 조명과 일반 수동 소등의 기존 0% 동작은 변경하지 않는다.

다른 조명 연동의 서비스 유지시간도 최소 1초로 설정한다. 이 시간은 마지막 수신 감지 신호부터 계산하며, 신호 간격보다 짧으면 소등/재점등할 수 있다는 기존 경고를 갱신한다. 센서가 신호를 보내지 않는 동안 사람의 지속 재실을 서비스가 추정하지 않는다.

## 서버와 Gateway의 저장 및 적용

- 자기 제어 여부와 다른 조명 대상 목록을 명시적으로 구분한다. 자기 제어가 켜졌을 때만 별도 실행 조명 0개를 허용한다. 둘 다 없으면 저장을 거절하며, 자기 조명을 일반 force 출력 목록에 끼워 넣지 않는다.
- 기존 규칙의 새 필드 기본값은 자기 제어 꺼짐으로 한다. 필요한 순방향 migration과 `docs/database-schema.md` 갱신은 실제 구현과 같은 작업에서 수행한다. 기존 행·ID·기본 밝기·등록 이력은 보존한다.
- 새 계약을 처리하지 못하는 Gateway는 자기 제어를 실행하지 않는다. 기능 지원과 현재 규칙의 정확한 적용 ACK를 확인하며, 오래된 ACK나 전달 완료를 장비 설정 완료로 표시하지 않는다. 기존 strict parser가 새 필드를 무시하도록 완화하지 않는다.
- 현재 물리 신원과 원 설정을 변경 전에 읽고 내구 저장한다. 자기 조명의 밝기·기본 밝기·유지시간·sensor 모드가 독립 조회로 모두 일치해야 적용 완료다. 설정 GET을 실제 광출력 확인으로 기록하지 않는다.
- 같은 조명의 여러 자기 제어 규칙이 경쟁하면 충돌로 거절한다. 일반 수동·스케줄·시간제 제어가 활성 감지 조명의 모드를 바꾸지 못하는 보호와 다른 활성 감지 조명의 일반 실행 대상 제한은 유지한다.
- 수정/비활성화/재시작 시 원 설정과 진행 원장을 보존한다. 부분 변경이나 조회 실패는 확인 필요 상태다. 비활성화 시 설정 소유권을 확인한 뒤 원 설정 복구를 검증하며, 다른 작업이 변경한 값을 과거 설정으로 덮지 않는다.

## 기존 및 신규 조명에 동일한 설정 제공

현재 UI의 6대 온라인 상태는 통신 상태이지 자기 제어 호환 증거가 아니다. 기존 조명도 최신 장비 식별과 공통 프로파일을 자동 대조한다. 이미 등록됐다는 이유로 새 기능에서 제외하거나 새 등록이라는 이유로 지원되지 않는 명령을 허용하지 않는다.

같은 검증 장비군은 공통 프로파일을 재사용한다. 다른 장비군에서 명령이나 시간 단위가 다르면 호환 처리를 추가한다. 일반 화면에는 설정값과 적용 상태를 표시하고 패킷·주소·fingerprint는 노출하지 않는다.

## 검증과 적용 순서

1. 기존 자료로 자기 감지 밝기·기본 밝기·유지시간 명령과 1초 표현을 확인하고 codec 회귀를 만든다. 근거가 없으면 활성화 코드를 추측하지 않고 확인된 범위와 필요한 장비 검증을 보고한다.
2. 공통 계약→서버→Gateway→화면 순서로 구현한다. 1초/잘못된 값/기존 저장값, 기존·신규 등록의 동일 처리, 자기 조명만 선택, 재감지, 소유권 충돌과 부분 실패의 원장 보존을 직접 관련 테스트로 확인한다.
3. PC·모바일에서 자기 조명 선택과 밝기/유지시간 저장·활성화 흐름을 격리 브라우저로 한정 확인한다. 무관한 기존 오류 수리나 전체 suite 반복은 포함하지 않는다.
4. 별도 브랜치에서 구현·문서·검증을 마친 뒤 메인 개발 브랜치에 병합한다. 서버 반영·Gateway 배포·실제 설정 쓰기·움직임 시험은 직전에 범위와 중단 시간을 알리고 승인을 받은 뒤 수행한다.

코드 완료와 장비 적용 완료는 구분한다. 실제 자기 감지·재감지 연장·1초 유지·기본 밝기 복귀가 확인되기 전에는 실사용 완료로 표시하지 않는다.
